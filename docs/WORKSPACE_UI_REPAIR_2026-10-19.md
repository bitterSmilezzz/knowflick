# 工作台 UI 修复与验收记录（2026-10-19）

## 范围与更正

先前提交 7a9b7b5 的说明「M1–M4 全链路跑通」不符合实际。此前没有三栏工作台、全局系统快捷窗口、向量推理、Office/PDF 解析或第三方插件沙箱；通过纯函数测试不能证明这些产品功能完成。

本次针对「前端几乎没有、无法实际使用」修复。以下仅记录已经实现和验证的行为，不替代原路线图，也不将未实现功能列为完成。

## 新入口与界面

`apps/workbench/src/main.tsx` 改为加载 `ui/workspace/Workspace.tsx`。旧 App 与既有算法保留供迁移，不再充当主界面。

- 固定三栏：左导航、中央内容列表与搜索、右侧阅读/编辑。各栏内部滚动，使用系统字体、紧凑按钮和明暗主题。
- 原生 dialog 录入：正文必填、标题可选、来源可选；Cmd/Ctrl+N 为**应用内**快捷键，Cmd/Ctrl+Enter 保存。失败保留草稿并显示原因。
- 素材从收件箱直接阅读编辑；保存为知识卡保留来源关联；归档能从已归档找回并移回收件箱。
- 全部知识、素材/卡片筛选、收藏、分类与标签、中文子串及多关键词搜索；长列表分批呈现，避免一次渲染全部行。
- 设置按外观、模型连接、内置复习开关分组。保存成功才回显；开关和主题重启后保留。密钥说明如实披露当前文件存储方式。
- TXT/Markdown 导入为素材；JSON 导入/导出包含素材与卡片，不包含密钥。Office、PDF、OCR、ASR 尚未接入。
- AI 提炼前检查连接；结果先预览再保存。浏览器模式明确提示桌面客户端才能使用 AI 和跨站抓取。
- 修复原问答模块对已提取文本再次 JSON.parse 的错误，使用统一 endpoint 解析；没有匹配卡片时不伪造知识库答案。

## 数据可靠性

桌面主入口使用 SQLite 单一路径写入，失败不上屏伪装成功；不再同时对全库 JSON 与 SQLite 进行未等待的双写。

修复空 dir 落入源码目录、首次父目录不存在、旧 ISO 日期和省略字段迁移失败、迁移反复复活删除数据、卡片 materialId/editedAt 往返丢失、素材更新字段遗漏与 hash 伪值。

卡片与索引写入共用事务；批量替换有真实故障注入测试验证回滚，迁移错误向界面传播。

浏览器体验仅使用当前浏览器 localStorage，明确标注与桌面 SQLite 分离。浏览器密钥使用当前标签页 sessionStorage；不把浏览器数据当成原生客户端的验证结果。

## 验收与复现

1. 在 `apps/workbench` 运行 `npm run dev`，为同一套 React 页面启动现有 Vite 地址（默认 http://localhost:1420）。
2. 在仓库根运行 `node tools/workspace_ui_smoke.mjs`。脚本需要本机 agent-browser，使用独立回归会话，清空的仅是该会话浏览器存储，不操作桌面真实库。
3. `./tools/verify_workbench.sh`：前端测试、TypeScript、Cargo 锁定依赖测试。
4. `npm run build`：生产前端构建。
5. 原生窗口：在 `apps/workbench/src-tauri` 运行 `cargo run --locked`（需已有 Vite），通过 macOS System Events 真实点击录入、保存、素材转卡；随后只读查询 SQLite 核对素材、64 位 SHA-256 和卡片来源外键。

UI 回归脚本已实跑通过 15 个断言：三栏存在、录入进入阅读区、保存按钮可见可点、正文刷新恢复、素材转卡、收藏持久化、两字中文检索、空搜索状态、归档保留原文、移回收件箱、设置保存可点击、主题与开关刷新恢复、模拟写入失败保留草稿并显示错误、Esc 关闭、无横向页面溢出。

原生客户端已验证：录入一条明确标记「界面验收记录」的内容，SQLite 原文已存在；点击保存为知识卡后外键关联正确、原素材状态为 processed。终止并重启客户端后，原生导航恢复「全部知识 2、已归档 1」，确认素材与知识卡仍可读取。截图位于 `.scratch/ui-repair/`（忽略文件，不入库）。验收记录留在本地库中，未删除用户内容。
