## Findings and disposition

### Confirmed finding 1, fixed — Modal background consistency (Design / Visual)

The initial review found that `WebClipModalView` returned a bare `VStack` without the standard dynamic background sheet wrapper (`ZStack { EditorialColor.dynamic(...) .ignoresSafeArea() ... }`) shared by all other modal sheets in the application (`ImportNotesModalView`, `ExportCardsModalView`, `SyncSheetView`, `SpeechConsoleView`, and `GlobalSearchModalView`). In macOS light/dark modes, this could cause the underlying window content or system default sheet background to show inconsistently behind translucent glass cards.

`WebClipModalView.swift` was updated to import `AppKit` and wrap the modal content with the standard 97% opacity window background `ZStack`, aligning with the existing UI design system.

### Confirmed finding 2, fixed — Release note checksum artifact filename (Documentation)

In `docs/MAC_RELEASE_4.4.3.md`, the verification checksum file was written as `附件 .sha256` instead of `附件 KnowFlick-4.4.3.app.zip.sha256`. This did not match the artifact packaging step in `.github/workflows/macos.yml` or previous release records (`MAC_RELEASE_4.4.2.md`).

`docs/MAC_RELEASE_4.4.3.md` was updated to specify the full filename `KnowFlick-4.4.3.app.zip.sha256`.

### Verified behavior and multi-platform alignment

1. **Two-step workflow**: Web clipping strictly isolates anonymous read-only fetching from AI transformation. Fetching never sends cookies, never persists cache, and displays the extracted title, canonical URL, and plain text preview first. Text is sent to the configured AI service only after the user explicitly triggers extraction.
2. **Attribution contract**: Newly created cards receive `source = .imported`, and the clipped page canonical URL is deduplicated and prepended as the first item in `links`, strictly matching the Android contract (`AiService.kt`).
3. **Queue insertion and deduplication**: The import action supports optional top-of-deck promotion via `store.importCards(selected, insertAtTop: insertAtTop)`, maintaining anti-collision spacing rules (`insertRespectingMinDistance`).
4. **Task lifecycle**: Both network fetch and AI transform tasks are tracked via `@State` tasks, cancelled on URL edits, and cancelled on view disappearance (`.onDisappear`).
