# 产品路线与验收

日期：2026-10-24。状态：建议实施顺序。R0–R5 是本次新路线，不与历史 M1–M4 的完成标记混用。

## 排序原则

每阶段发布一个完整可用的增量。先解决数据可靠、持续写作和找回，再扩大来源、跨端与应用；完整需求留在 [能力目录](CAPABILITIES.md)，阶段未包含的部分进入后续批次。

阶段存在依赖而非必须串行开发：R2 原文切片依赖 R1 笔记修订；R3 同步依赖稳定的数据包与删除语义；R4 画像依赖来源与授权；R5 插件生态依赖已经运行过的官方扩展接口。已有 MCP 和复习继续可用，不等到 R4 才允许使用。

没有确定团队人数、每周投入、最低配置设备和真实账号，暂不写“某月全面完成”。估算按完成首个笔记批次后的实际吞吐更新，不能把 AI 生成代码速度当产品交付速度。

## R0：让现有承诺可验证

交付：可安装的当前基线、现状能力/缺口、可恢复备份与一组固定的真实工作流。

工作项：

- 复跑剪藏 → 出卡 → 复习/测验 → 导出，并验证旧数据与学习进度。
- 真实邮箱按服务商分别测：QQ 授权码与 TLS；163/126 先核实当前官方认证要求，再做真实账户验证；Gmail/Microsoft 若当前 LOGIN 不适用，标为需 OAuth，不给兼容承诺。
- 真实桌面麦克风录制、保存、重启、回放与导出；扫描 PDF、长录音、大媒体按实际能力报告结果。
- 用户自选本地或外部模型，分别测出卡、问答与引用；没有可用账号时列明待验，不用假响应冒充。
- Windows/Linux/macOS 各做安装首启与升级恢复；当前机器只能完成其可验证平台，另外两平台须有执行人/CI 与真实安装记录。

退出门槛：各项分为可用、有限可用、待验或失败；界面陈述与证据一致。阻塞外部账号时，独立的本地笔记开发仍可推进；相关连接器不得标已完成。

## R1：成为每天可以写的笔记产品

交付：本地桌面首个闭环——**随手记录 → 持续编辑 → 加入知识库 → 全文找回 → 恢复与导出**。不需要 AI 也能完成。

覆盖：A01/A03、B01–B03、C01/C04 字节基础/C07/C08、E01/E08 基础/E09、F01。已有 A02/D02 保留并回归。

实施顺序：

1. 修订模型与迁移：原素材不丢，旧卡片 id/评分保留；设计开放导出与恢复。
2. 可持续编辑笔记：基础格式、附件引用、自动保存、草稿与修订、回收站；新建与编辑走同一路径。
3. 三入口导航：笔记/知识库/应用；旧入口逐一映射，快捷键与深链接回归。
4. 笔记本、标签、收藏、库成员；保存即能全文搜索，不要求 AI 出卡。
5. 最小官方模块生命周期：关闭后停任务、内容仍可读；旧用户启用状态保留。

退出门槛：断网、无 Key、重启、磁盘写失败与意外退出均有可解释结果；新手能独立续写并找回；完整备份到新目录恢复后正文、附件、出处及学习进度一致。

这是“最小但完整”的产品，不是功能总量最小的演示壳。未完成这一阶段前，避免同时开十个来源适配器与插件市场。

## R2：多源笔记与可信知识库

交付：网页、文件、图片、录音/会议、邮件与首批外部笔记都进入统一笔记模型；原文能够被检索、引用和用于学习。

覆盖：A02/A04–A06/A08–A11/A13/A14 首批、B04–B07/B10 基础、C02–C07、D01/D02 衔接、E05/E08 生命周期。

先做两条实际高频来源链路，建议网页+文件，再按使用频率扩到会议、邮件与导入：

- 导入向导：格式检测、转换报告、附件、失败清单、重复候选与幂等重跑；先通用格式，再品牌适配。
- 文本与多媒体混排；OCR/ASR 异步、可取消，保留原件、时间点及修订后的转写。
- 正文分块索引与版本化向量空间；检索不只看卡片，关闭 AI 仍可搜原文。
- 多来源引用、矛盾与过期提示；真实查询集衡量检索和回答质量。
- 邮件授权适配。首批可先交付 QQ/163 的实测只读连接和 Gmail OAuth；Microsoft OAuth 按实际用户需求同阶段分批。每一提供商通过自己的验收后才展示可用。

退出门槛：不同来源都完成“导入 → 搜索 → 打开原件 → 引用 → 修改/删除后的更新”；来源失败可重试且不重复建笔记；会议纪要与问答的关键断言可核对。禁止仅以支持扩展名数量验收。

## R3：自选同步与手机/平板基础

交付：桌面 + Android 可交换并安全使用同一套笔记；用户可以选择自己的存储，无我方云账号依赖。

覆盖：A07 基础/A12/A14 移动、C08 新协议、E02–E04、F02/F03 基础。

推荐交付顺序：

1. 版本化备份包复制到用户指定目标，成功后可在另一台设备恢复。明确这是备份。
2. WebDAV 第一驱动；选一个真实自建服务与一个实际用户服务跑兼容性。先展示单向复制，再开放经过验证的双向变化合并。
3. S3 兼容驱动（例如 MinIO）与 E2EE，同一套冲突/中断/恢复测试。同步开箱不需要开启，但开启后的保护级别必须如实说明。
4. Android 先支持新笔记只读与无损保留，再开放编辑、分享/拍照/录音与可靠离线队列；平板先双栏与基本笔迹。
5. 再评估 Dropbox/OneDrive/Google Drive 独立 API，不能仅因 WebDAV 驱动存在就标记这些服务已支持。

退出门槛：两台设备离线改同一笔记、反复重试、删除冲突、附件只上传一半、密钥恢复和旧客户端均不静默丢数据；手机不支持的块只读保留，不能写坏桌面笔记。

## R4：复盘、个人记忆与外部工作流

交付：用户能从指定范围完成周报/项目复盘、目标回顾与内容创作，并把项目记忆提供给外部 AI。

覆盖：C05 维护、D03–D09、E06/E07。

实施顺序：

1. 有来源的复盘与项目上下文，区分记录事实和建议。
2. 用户明确设置目标与完成条件，关联进展证据；“缺少记录”不得判为失败。
3. 我的记忆与偏好：先确认事实，再增加可纠正的推测；范围、有效期、撤销和阻止复活。
4. MCP 升级为独立客户端/项目授权，默认只读；所有入口统一策略，既有写工具按显式授权迁移。
5. 开发、营销、自媒体、研究等以应用模板先验证；Skill/上下文包列明宿主与版本，静态副本带日期。

退出门槛：删除或否认的记忆不继续用于后续回答；项目 A 无权读取项目 B；每个引用可回原件；外部应用吊销后失效；创作草稿可以检查、修改与导出。外部代发与自动执行是独立模块，不因可生成草稿就自动获得权限。

## R5：高级笔记与扩展生态

交付：在前述闭环稳定后，逐批增加高级编辑、数据视图、画布、精细手写、更多连接器、Web 与第三方插件。

覆盖：A06/A07 强化、A11 长尾、B07 增强/B08–B11、C06 图视图、D07/D08 增强、E07/E08 生态、F03 强化/F04。

每批按独立价值验收：

- 多视图与属性：一份内容多种视图，公式与关系不破坏导出。
- 白板/局部图谱：限制加载规模，编辑器不受图渲染阻塞。
- 平板：真实触控笔的压感、套索、防误触、手写搜索。
- 第三方连接器：能力矩阵、故障可诊断、可停用和卸载；先单向再讨论双向。
- 插件：受控运行时、最小权限、版本契约、更新与崩溃隔离；开放市场在运行时成熟之后。
- Web：文件、权限、后台和本地推理分别验收；自建服务模式单列。
- 分享发布、评论与协作编辑：先验证个人用户的真实需求，再以可选自建模块设计身份、权限与同时编辑；保留为能力方向，不挤占本地闭环。

这些是长期能力池，不承诺 R5 单次全量上线。iOS/iPadOS 需独立平台决策，不恢复旧 Swift 桌面工程。

## 首个开发批次

建议下轮直接从 R1 的一个纵向切片开始：

**新建一篇可持续编辑的本地笔记 → 自动保存与重启恢复 → 加入一个知识库 → 搜索命中正文 → 完整导出并恢复。**

先写修订与迁移契约，再实现基础编辑和这条链路，最后接三入口导航。首批不扩大第三方服务数量，确保新增笔记与旧卡片不互相覆盖。R0 可独立验证的缺口同时补证。

若按两周一个交付节奏组织，第一轮的目标是这条链路与真实用户试用，不是两周完成全部 R1–R5。两周只是建议迭代周期；工作量需模型/编辑器/迁移小样后重新估算。

## 统一质量目标

以下是**待基准校准的建议发布门槛**，不是当前测试成绩。

### 数据与正确性

- 备份往返：固定样本的正文、附件字节、修订引用、来源和学习状态全部一致；故障注入不静默丢最后一次已确认保存。
- 去重：相同 Blob 只占一份，语义相似不自动删除；历史修订与新内容可区分。
- 删除：全文、向量、应用和 MCP 后续都不返回已撤销内容；备份和离线设备规则有解释。
- 权限：跨知识库、项目、私密标记、外部客户端的负向用例全部拒绝。

### 搜索与 AI

- 建立至少 100 条中英混合的可审阅检索问题，含两字中文、人物、编号、同义表达、否定、过期与无答案问题。
- 有正确来源的查询，首 5 条来源命中率目标 ≥90%；问题与标准答案由人工标注，版本固定，按来源类型分报。
- 对同一批问答人工检查引用：涉及个人资料的关键事实目标 ≥95% 有支持它的有效引用；编造来源和越权引用为 0 容忍门禁。
- 无答案与矛盾场景单列报告拒答/说明是否正确；单一“平均正确率”不能掩盖严重问题。

### 性能与容量

先确定 8GB 内存、普通 SSD 的参考桌面与一款目标 Android 设备，分平台实测；模型运行与空闲状态分别报。

- 基准集：1 万篇笔记、10 万切片，加现实大小附件；记录字数与媒体总量，不能只报条数。
- 无大模型运行时，桌面可编辑首屏目标 ≤2s；键入交互 p95 ≤50ms；本地全文搜索首批结果 p95 ≤300ms。
- 语义检索/模型生成/转写另报首结果时间、吞吐、峰值内存与能耗；不宣传所有 AI 任务毫秒完成。
- 重任务队列并发默认 1，支持暂停、取消、重试与模型释放；任务执行时基本编辑仍满足交互预算。
- 原件、派生索引、缓存、模型分别计量。关闭模块后验证没有对应后台任务，不以“零内存”代指整个程序无任何模块元数据。

### 产品与跨端

- 5–8 人两周试用：独立完成记录、续写、找回、有出处使用和恢复；记录成功率、耗时、放弃点。样本小，不能包装成市场统计。
- 桌面三系统安装/升级/退出重开；Android 真实分享/录音与平板触控笔；键盘/读屏/输入法/浅深主题均有证据。
- 每阶段保留原九项学习闭环与 Android 既有能力的回归。修改 `shared/**` 或协议时，两套实现都过对应门禁。

## 工作管理与证据

每个任务引用能力编号、阶段、实际入口、测试/人工证据与已知限制。状态统一为：规划、实现中、待真实验收、有限可用、已验收；不能用一个勾号同时表示代码存在与真实可用。

遇到范围增加，先更新本目录的能力编号和依赖，再开小批次实现。GitHub 协作和各平台验证沿用仓库规则；本规划不自动合并当前长期分支，也不自动发布版本。
