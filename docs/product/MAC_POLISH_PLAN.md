# mac 端尽善尽美：优化计划

> 范围：macOS 上的 KnowFlick Workbench（`apps/workbench-go` + `apps/workbench`）。
> 基线：0.9.0-rc2（2026-11-24 发布，四档安装包 + provenance 校验通过）。
> 口径：每条都写清**现状证据**与**验收方式**；不能自动化的标「需真机」，不假装已通过。

## 0. 为什么先列计划

rc2 已经在真机上跑通核心闭环，但 macOS 端仍有若干**「在别的平台看不出来、只有 mac 用户天天遇到」**的缺口：
原生菜单栏没有应用自己的命令、拖文件进窗口不生效、窗口位置尺寸不记忆、首次启动是「只读 + 手动开库」两步、
快捷键只在 WebView 内有效而系统菜单里没有、通知走 `osascript` 而非原生通知中心。

本计划按**「用户可感知的原生感 → 数据安全 → 可运维」**三档推进，每档都有可验证的完成条件。

## 1. 现状盘点（已核对代码与真机）

| 维度 | 现状 | 证据 |

## 2. 优化清单（按优先级）

### P0 —— 原生感（mac 用户第一眼就能看出差别）

**P0-1 应用原生菜单栏**
给 macOS 装一套**中文**应用菜单：关于 KnowFlick / 记一条(⌘N) / 搜索(⌘K) / 知识测验 / 导出备份 / 设置(⌘,) / 快速捕捉(⌥Space)，
加上标准的编辑、窗口、帮助组。菜单项通过事件桥驱动前端，不在 Go 里复刻业务逻辑。
- 验收：真机 AX 树里菜单项文本为中文且各项可用；⌘, 能打开设置；⌘K 不覆盖已打开的面板。
- 现状依据：Wails v3.1.0 提供 `app.Menu.Set`、`NewAboutMenuItem` 等角色菜单（已在 `~/go/pkg/mod/.../pkg/application/roles.go` 核对）。

**P0-2 拖文件进窗口**
开启 `EnableFileDrop: true`，给收件箱容器加 `data-file-drop-target` 标记与激活态样式，
并让原生拖放路径走 Go 的「按路径读文件」接口（浏览器 File 对象拿不到真实路径）。
- 验收：把 .md 拖进窗口 → 收件箱出现该素材；拖 .kfbackup → 走恢复流程。

**P0-3 记忆窗口位置与尺寸**
把窗口位置/尺寸/是否最大化写进 `settings.json`（不进库），下次启动恢复；位置需校验仍在可见屏幕内。
- 验收：改窗口大小 → 退出 → 重开，尺寸与位置一致；换到副屏后不恢复到屏外。

### P1 —— 流程与数据安全

**P1-1 首次启动直接可写**
新装时库已由应用创建，却还要用户点一次「启用编辑」——这是**多余的一步且容易让人以为应用坏了**。
改为：首次启动若库由本应用创建，直接以可写打开；打开「别人的库」仍保持只读（ADR-0009 边界不变）。
- 验收：新库首启即可写入；外部库仍显示「只读」。

**P1-2 单实例**
开启 `SingleInstance`，第二次启动时聚焦已有窗口而不是再开一个进程。
- 验收：连点两次图标 → 只有一个进程、窗口被前置。

**P1-3 快捷键全链路**
在原生菜单上声明 ⌘N/⌘K/⌘,/⌥Space，使系统在应用未聚焦时也能响应「隐藏应用时按 ⌘N」的常见期待；
同时把快捷键清单集中到一处，界面帮助与菜单共用同一份定义，避免文案漂移。
- 验收：菜单里看到的快捷键与界面帮助一致；聚焦别的应用时按全局 ⌥Space 能唤出捕捉窗。

**P1-4 通知改用原生通知中心**
用 `UNUserNotificationCenter`（或 Wails 的通知封装）替代 `osascript`，支持图标、分类与点击回调。
- 验收：主动回顾提醒出现在 macOS 通知中心（含应用图标）；点击可跳到复盘页。

### P2 —— 打磨与可运维

**P2-1 日志文件**
日志写 `<data_root>/logs/knowflick.log`（滚动保留 7 天），并在设置页给一个「打开日志目录」入口；
用户报障时可直接取证，不必让对方开终端。
- 验收：设置页能打开日志目录；日志里能看到建库、打开库、导入等关键动作。

**P2-2 窗口细节**
启动窗口居中、最小尺寸合理、⌘W 关闭后应用不退出（改为隐藏到 Dock，符合 mac 习惯）或明确退出语义；
暗色模式下标题栏跟随系统。
- 验收：暗色系统下标题栏与窗口底色一致，不出现「白底黑字」的割裂。

**P2-3 性能与体积**
首启时间（1.27s）与内存（~120MiB）已达标；进一步做窗口复用、隐藏时暂停轮询、附件目录惰性扫描。
- 验收：给出改动前后的首启耗时与常驻内存对比。

**P2-4 无障碍与中文排版**
补 `aria-label`、键盘焦点顺序、对比度检查；中文长标题换行与标点挤压。
- 验收：VoiceOver 能读出主要区域；键盘可完成「导入→测验→导出」。

## 3. 执行顺序与依赖

1. **P0-1 菜单栏** 先行——它同时是 P1-3 快捷键的落点，也是 P2-2 窗口语义的入口。
2. **P0-2 拖放** 与 **P0-3 窗口记忆** 相互独立，可并行。
3. **P1-1 首启可写** 依赖 P1-2 单实例（否则两个进程会同时写同一个新库）。
4. **P1-4 通知** 需要 Go↔前端事件桥，与 P0-1 共用同一套桥接。
5. **P2** 全部在 P0/P1 稳定后再做。

## 4. 验收与发布

- 每条改动都要有：Go 单测或前端单测（能自动化的）+ 真机操作记录（AX 树/数据库/文件系统三类证据之一）。
- 完成后打 `workbench-v0.9.1-rc1` 预发布，沿用现有四平台流水线与 provenance 校验。
- macOS 侧新增的安装后首启检查扩展为：启动 → 菜单栏出现应用菜单 → 建库成功。

## 5. 明确不做（本轮）

- **不做付费代码签名与公证**：按所有者决定，证书等商用可行性后再申请（见 `docs/product/GA_PLAN.md` WP3）。
- **不做窗口分屏/多窗口**：产品主线是单窗口工作台，多窗口会稀释「一屏串通」的设计。
- **不做 iOS**：仍按 ADR-0002，iOS 先不做。
