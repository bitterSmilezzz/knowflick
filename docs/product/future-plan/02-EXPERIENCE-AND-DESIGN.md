# 02 · 界面、交互与视觉设计

盘点日期：2026-11-12。本文区分**当前可见**、**规划目标**和**建议待定**：当前可见指本次核对的工作树代码，包括尚未提交的界面；它不等于已发布或所有设备均已验收。已确认的视觉原则以 [界面设计规范](../../UI_DESIGN_SPEC_2026-10-19.md) 为准；笔记优先的信息结构和后续平台交互以 [产品界面方案](../UI_SPEC.md)、[ADR-0004](../../adr/0004-notes-knowledge-applications.md) 为准。实际通过、失败和跳过记录见 [验收运行记录](../ACCEPTANCE_RUN.md)。

## 用户打开 KnowFlick 要完成什么

1. **记下来**：随手记一段字、收一封邮件或一个网页，也能继续编辑一篇长笔记。进入时不必先分类或选择 AI。
2. **找得回**：从笔记或指定知识库查到原文；认得出这是笔记、原始素材、知识卡，还是生成产物。
3. **用得上**：在明确的资料范围内问答、学习、复盘、看目标或写草稿；结果能回到证据。
4. **带得走**：能单独导出笔记与附件，也能在设置里查看整库备份的实际覆盖范围和恢复结果。

默认呈现为安静的工具工作区。内容、一个主要动作、当前范围和状态先出现；来源配置、AI、筛选和高级属性按场景展开。学习卡片的摄影底图是学习场景的例外，编辑器、知识库和设置不沿用同样的卡面。

## 信息结构和入口迁移

| 位置 | 当前可见 | 规划目标与迁移要求 |
| --- | --- | --- |
| 全局入口 | 左栏「记录」打开闪念；下面有手写、语音、转写、笔记转卡。顶栏保留导出备份。`Cmd/Ctrl+K` 聚焦集合搜索；在其他页面可切回「全部知识」搜索。 | 一级目的地仍只有「笔记 / 知识库 / 应用」。保留一个显著的新建动作与全局搜索入口；新建默认开始写笔记，展开后才见录音、手写、剪藏和导入。高频记录方式可固定。原闪念快捷键和动作保持可达；命令面板是解决导航过深的可选方案。 |
| 笔记 | 「全部笔记」「收件箱」「邮箱」「订阅源」是笔记组内直接入口；「导入文件」是动作，最近一次导入报告可展开；笔记页本身有笔记本筛选与回收站。 | 首屏聚焦最近、收件箱和继续写；笔记本、收藏、归档、回收站是组织视图。邮箱、订阅、文件及外部笔记接入收进二级「来源管理」，常用来源可固定。未处理计数、文件导入和旧入口保持可达。 |
| 知识库 | 「全部知识」是入口，收藏和已归档收进筛选；分类可展开。集合工作面已有来源类型、笔记/素材/卡片筛选与知识库范围；笔记编辑器内可创建库、加入多个库或移出。 | 提供全部内容、我的知识库、项目与待整理视图；最近的 2–3 个知识库可固定。范围始终显式；主操作聚焦库内搜索、提问、整理。规则配置归到库设置；库概览、内容和局部关系视图分步交付。 |
| 应用 | 折叠组内有知识问答、认知简报、产物库、统计、知识测验、复盘、我的记忆、目标、项目记忆、创作台；温故复习按学习插件设置在折叠组外显示。应用页打开时对应组展开，当前导航项会滚入可视区。 | 按问答、学习、复盘、创作和项目工作组织；首次使用只推荐少数适用项，可添加或固定。升级保留既有模块状态、卡片、产物与学习进度；应用目录及模块入口不能把旧功能变成找不到的孤岛。 |
| 设置与状态 | 侧栏底部「设置」与存储位置状态；顶栏仍能导出备份，应用的原生文件菜单也有导出；页面有保存、忙碌与错误回执。 | 设置按外观与操作、数据与备份、来源、模型与 AI、同步、功能模块、隐私与外部访问分组，可搜索。备份最终归文件菜单和数据设置；单项导出跟随笔记或项目。状态只反映真实本地写入、同步或失败。 |

规划中的可达目标：开始新笔记 ≤1 次点击，收件箱／搜索／当前知识库 ≤2 次，来源连接／批量导入／模块管理 ≤3 次。导航重排先补旧→新入口对照，再迁移，不仅测按钮还在，还要测能打开正确页面、保留输入和回到正确上下文。`knowflick://` 的内容引用不等同于桌面壳已提供可从系统任意启动的 URL 深链接；后者未单列验收。

## 桌面页面和主要交互

| 工作面与能力 | 当前可见 | 下一步界面与交互要求 |
| --- | --- | --- |
| 首启和恢复工作位置（A01、F01） | 启动页状态从收件箱开始。空集合、空笔记和无搜索结果有不同提示。 | 首次进入只给首条记录的主动作、必要时补导入或连接来源；返回用户可继续上次可恢复的工作位置。保留筛选、选中项及未存草稿需逐项验收，目标内容已删除时回到可操作的列表。 |
| 闪念与全局捕捉（A01–A03） | 主窗口内的文字闪念弹层可选填标题和 URL，保存为收件箱素材；原生托盘和 `Alt+Space`（macOS `Option+Space`）有独立文字胶囊。胶囊成功写入才清空，保存失败保留文本，`Esc` 隐藏期间保留内存草稿；主窗口弹层和进程退出没有统一的持久草稿机制。 | 主动作新建完整笔记；全局快捷键、托盘和可选灵感球共用捕捉语义。先保留用户输入，再异步处理网址；权限、登录或网络问题给出粘贴正文/重试。成功回执给目标位置和查看入口；退出、切页和异常重启都能说明草稿保存情况。灵感球位置、显示及全屏行为为后续目标。 |
| 收件箱、素材阅读和出卡（A02、C03、C05、D02） | 列表与正文同屏，可按来源筛选、归档素材；详情可「转为可编辑笔记」，保留原素材。提炼为知识卡默认折叠，支持 AI 预览与勾选确认。 | 收件箱显示尚未处理/失败的来源和下一步；打开原件、转笔记、归档、重试按对象提供。用户写的正文直接可搜，AI 摘要、事实和知识卡先预览，允许选择、更正或取消。不能把忽略待整理项当成错误。 |
| 编辑和笔记组织（B01–B06） | 编辑器为标题、Markdown 正文输入框和折叠预览，自动保存并显示状态；支持笔记本、标签、收藏、回收站恢复、引用笔记/素材和插入既有附件引用。检测到冲突时有覆盖、另存副本和加载最新内容。录音、手写的新建主要仍走素材链。 | 编辑顶部保留标题、保存状态和常用操作，选中文本或斜线菜单可提供格式工具；键盘和显式工具入口同时保留。正文内直接插入或创建图片、录音、笔迹；检查器按需展示来源、属性、反向链接和历史版本。补齐基础格式、查找替换、批量整理、可见的版本恢复；所见即所得的具体编辑方案仍待定。 |
| 手写、录音、图片和视频（A04–A08、B06/B07） | 有独立手写板、按笔撤销与清空；桌面语音支持采集后存音频及可选本地转写。浏览器可预览手写，不能把录音持久保存为桌面附件；物理麦克风链路待验收。 | 手写和文字可在同一笔记编辑；录音先落盘，再转写，清楚显示录制、保存、转写中、待模型和失败。原音频可回放，转写可编辑，纪要可定位时间点，默认不代发。OCR 以可修订派生层展示；视频字幕和批注同理。压感、套索、橡皮擦、防误触和真实触控笔体验分阶段。 |
| 导入、邮箱、订阅与外部笔记（A09–A14） | 文件选择、拖放、格式识别、部分失败/跳过回执与最近一次持久报告。邮箱有账号连接、测试、手动同步、旧邮件分页、隔离重试、搜索、归档和汇总；订阅有添加与抓取入口。邮箱能力依赖桌面，服务商预设不是 OAuth 或真实兼容证明。 | 来源管理展示授权、范围、过滤规则、最近成功、部分失败和可重试项；导入预览每种格式的原件、链接、标签和附件保留情况，允许只重试失败项。外部笔记连接明示一次导入、持续拉取或双向同步；无法保留的内容逐项告知。平台 OAuth、专有格式及监视文件夹按路线另验收。 |
| 知识库、搜索和整理（C01–C07） | 集合搜索支持筛选、命中高亮、最近查询，笔记工作面有笔记搜索。正文块可检索，笔记/素材引用可回原件，并提示已修改或缺失。近似重复当前有候选提示。 | 结果同时标类型、出处、命中段落及范围；无语义模型时继续全文搜索。库内整理呈现分类、近似重复、矛盾和需复核的候选，保留原出处并支持撤销；并排对比为后续增强。索引失败、换模型或重建进度放管理面，索引是派生数据，清理不会丢原件。 |
| 知识问答、认知简报和产物（D01、D03、D07） | 问答与简报已有入口；工作树含按项目范围检索、来源定位和授权的个人记忆选项；产物库可打开仍存在的笔记来源并标注失效。 | 先选资料范围，区分仅检索本地、联网补充和发送给配置模型；回答与证据并排或可展开，链接定位到段落、页或时间点。资料不足直接说明，缺失/失效引用留提示。产物保留来源与版本，转为笔记由用户执行，默认不反向喂入画像。 |
| 学习和统计（D02） | 出卡、卡库与详情、收藏、卡片历史、测验、复习及统计有既有入口。温故按启用配置展示。 | 保留评分、进度、历史、底图和导出；通过笔记及知识库上下文进入相关卡片。区分卡片复习和生活/工作复盘，停用学习入口仍保留数据并能重新启用。 |
| 复盘、目标与提醒（D03、D04、D09） | 日/周/月和项目范围；显示有记录的事实、可回原件的证据和缺记录部分；目标要求完成条件及用户确认，支持选笔记作证据。工作树有提醒频率、安静时段及独立通知授权，也有预览发送来源、逐次同意的 AI 建议区。 | 同屏区分事实、缺记录、可处理事项和 AI 建议；来源无法读时显示「不可用」，不写成 0。目标没有证据不自动判失败。提醒支持暂停/关闭和项目范围，仅为可处理事项发送；显示通知权限/系统限制。AI 建议可核对、采纳或驳回，默认不改目标或自动写回。 |
| 个人画像（D05） | 「我的记忆」展示事实/推测等类型、状态、范围和证据；用户可选笔记逐次同意生成提案，笔记可标记排除；生成先进入待确认状态。问答用不用记忆另有逐次同意。 | 继续明确已确认、待确认、失效、暂停、否认等状态及证据归属；撤销后不进入后续请求。全局与项目分开，不把收藏或阅读行为自动等同于认同。外部真实模型和真实资料体验另验收。 |
| 项目记忆、创作和应用模板（D06–D08、E07） | 项目可创建、管理成员、封存和导出 Markdown／技能包；创作台从笔记与卡片挑证据，生成可改的大纲并保存产物或导出。当前初稿是证据与模板拼装，未调用模型；工作树含范围切换、旧证据清理及导出约束。 | 先确认范围，再展示成员、决策、约束和未决问题；模板只提供任务结构，仍让人审稿和核查出处。模型起草另分期。范围切换不能偷偷携带旧项目证据，清除草稿的提示和留存策略应在交互稿中明确。外部技能包注明范围、日期、目标宿主和静态副本不可撤销；不在此流程代发内容。 |
| 设置、备份与外部授权（C08、E02–E08） | 设置有外观、快速记录、模型连接、官方模块、备份恢复、WebDAV、MCP 接入；工作树含项目只读授权及撤销。WebDAV 现是单向快照。 | 配置页分别说明模型下载/可用/失败、来源授权过期、模块开关与保留数据、备份覆盖/跳过/冲突。恢复前能看来源和范围，完成后能回看失败清单；同步上线后才显示设备、队列、冲突和恢复密钥。外部授权显示访问范围、读写权限、有效状态及撤销；停用或撤销后的操作要得到明确拒绝。 |

## 风格、部件与窗口尺寸

已确认视觉方向是**中性冷灰、系统字体、原生工具感**。以下实现对照以 [tokens.css](../../../apps/workbench/src/ui/workspace/tokens.css)、[workspace.css](../../../apps/workbench/src/ui/workspace/workspace.css) 和 [Icon.tsx](../../../apps/workbench/src/ui/workspace/Icon.tsx) 为依据，旧稿中的其他主题名、暖赭衬线、营销式欢迎页不作为新界面基线。

| 部件 | 实施基线 |
| --- | --- |
| 颜色与主题 | 默认跟随系统，可手动选浅色/深色。浅色 `#F5F6F7` 背景、`#FFFFFF` 内容面、`#1C1E20` 正文；深色 `#1B1D1F`、`#232629`、`#E6E8EA`。应用壳可用轻微材质，内容面保持清楚实底。强调色跟随系统并有冷蓝后备；使用 `--accent-solid`/`--accent-text` 对应实心按钮和强调文字。旧规范中的用户自定义强调色要以实际入口验收，目前设置页主要实现三档外观。 |
| 字体、排版与密度 | 系统无衬线，中文回退 PingFang SC、Microsoft Yahei 等；代码用系统等宽字体。正文 14px / 1.6，元信息最小 12px，主页面标题参考 17px。长文约 68 个中文字符以内的阅读宽度是设计目标；列表优先标题、时间和来源摘要，不用彩点或卡墙抢视觉，标题可截断但不可被挤没。 |
| 控件、图标和焦点 | 控件圆角 4px、面板 8px，按钮/输入约 28–32px；`tokens.css` 常用高度 30/32px，工具栏 42px。统一线性图标（`viewBox 24`、笔画 1.65），图标按钮要有可读名称。普通文字对比度 ≥4.5:1；承载状态的边框、图标和焦点环 ≥3:1，装饰细线不承担识别任务。 |
| 层级和动效 | 主按钮只给当前关键动作；其他操作使用轻边框、链接或折叠。空间和细线区分导航、列表与正文，避免装饰性渐变和大投影。动效只反馈操作，常用令牌 120ms；减少动态效果时取消过渡和录制脉冲。新增页面复用主题令牌，不写出两套全局 CSS。 |
| 分栏与平台材质 | [paneLayout.ts](../../../apps/workbench/src/ui/workspace/paneLayout.ts) 默认导航 200px、列表 320px，拖动区间 160–360 和 240–480px，计算时预留 360px 正文；≤980px 导航默认折叠，手动可覆盖展开；独立记忆宽度，可用键盘调整和双击复位。旧视觉稿约 1100px 为初始建议；当前断点以上述实现为准。宿主主窗（Go/Wails v3）当前 1080×720、最小 380×440（以 `apps/workbench-go/main.go` 为准；旧 Rust 版那组 1040×760 / 880×640 的数值已不再对应）。macOS / Windows 的窗口材质与系统菜单需真机核查，浏览器圆点是预览装饰。 |

窄窗口仍须能写和读。桌面先折叠导航；当列表与正文无法同时保留可读宽度时，后续增加「列表 ↔ 阅读/编辑」单栏回退，避免硬挤。设置、问答和应用子页沿用同一个壳，内区按任务选一或两栏。正文、列表各自滚动；复习这类连续任务应避免内外双滚动让底部动作被遮。320px 列表默认值不等于手机或平板要复用同一布局。

当前快捷键：`Cmd/Ctrl+N` 录入、`Cmd/Ctrl+K` 搜索、`Cmd/Ctrl+E` 编辑当前集合条目；`/` 聚焦搜索、方向键或 `j/k` 浏览、`Enter` 聚焦阅读、`Shift+方向键` 范围多选；侧栏支持 `Ctrl+Cmd+S` 或 `Cmd/Ctrl+Shift+S`。独立胶囊的设置和标题按 macOS `Option+Space`／其他桌面 `Alt+Space` 显示；快捷键注册失败仍可走托盘或原生文件菜单，不能视为所有系统都注册成功。侧栏「记录」目前仍写 `⌘N`，Windows/Linux 提示需要校正。后续新增操作必须可键盘到达，`Esc` 退出弹层或覆盖导航并还原焦点；先测中文组合输入、长按重复触发和系统冲突。

```text
列表 → 全屏阅读或编辑 → 系统返回列表
[笔记]          [知识库]          [应用]
```

用于原型评审的三条状态切换：① 闪念写完 → 本地保存成功 → 回执带「查看收件箱」；若网页抓取失败，仍能看见原记录并重试。② 笔记续写 → 保存冲突 → 看两版和来源 → 用户决定另存、加载或覆盖；切换后可确认原输入保留在哪里。③ 知识库提问 → 选项目范围 → 检查将发送的材料 → 查看回答与原文；改范围后明确告知是否重置本轮草稿和证据。按钮位置、文案与比较面板形式需在实测后定稿。

## 空态、失败和授权：每屏要能回答「接下来怎么办」

| 状态 | 必须给出的信息和动作 |
| --- | --- |
| 空库／空搜索／无权限 | 区分没有资料、筛选无结果、未授权；分别给新建、清除筛选、申请权限或替代路径。关闭模块的可解释入口支持键盘，不靠悬停说明。 |
| 保存中／保存失败／磁盘满 | 显示实际保存状态；失败时说明草稿位置，保留可复制内容、提供重试和处理空间入口；未落盘不显示成功。切页和退出的保护与写入状态一致。 |
| 离线／部分导入失败／授权过期 | 已保存内容可继续读写；明确哪个来源或文件失败，提供可回看的结果及仅重试失败项的目标路径。取消后说明保留了哪些输入和原件。 |
| 录音权限拒绝／任务暂停／模型不可用 | 说明要去哪打开权限或如何换方式；已录原件和转写进度分开。下载、加载、处理中、取消与失败各有状态，AI 不可用仍能写、读和查。 |
| 过期引用／原件缺失／范围加载失败 | 提示哪个来源变动或缺失；不伪造跳转或统计值。未能读取范围时停在当前范围或空结果，不悄悄查全库。 |
| 同步冲突／恢复中／旧版只读 | 明示设备、版本和保留路径；对照后选择本地/另一版/另存副本。恢复回执列新增、跳过、失败和未覆盖数据，重复导入不能重复新增。旧客户端无法编辑的块保持原样。 |
| AI 与外部访问 | 发送前能看到数据、范围、目的地，个人记忆和项目记忆逐次选择。建议和事实视觉/语义分离；撤销、断开或停用后给真实状态和后续影响。 |

状态既用文本也用适当的语义：持久反馈区通过 `role="status"` 宣布状态变化，重要失败使用 `role="alert"` 并保留可回看报告；不要用颜色、图标、消失很快的提示条或随时间变化的数字作为唯一信息。弹层需要初始焦点、循环/退出、可读名称及返回焦点；涉及删除、覆盖和外部访问，要在确认前看到对象、影响和可撤销性。

## 分阶段交付与验收

- **当前先收口**：用 [R1 记录](../R1_PROGRESS.md)、[R2 记录](../R2_PROGRESS.md) 和 [R4 记录](../R4_PROGRESS.md) 对照旧入口、续写、导入报告、原件定位、项目范围、复盘、授权与恢复；优先补真实设备、真实数据和真实模型的缺口。已在 macOS 隔离条件通过的环节只按其测试边界登记。
- **R3/R5 跨端**：依次交付 Android 只读、记录/编辑及离线队列、平板基础和笔迹增强；浏览器可用能力单列。多端冲突和跨端附件恢复、实机分享/录音/笔触不能靠浏览器模拟通过。
- **后续设计稿**：按「编辑与捕捉 → 可信来源和知识库 → 设置和扩展」交付交互原型；每个稿附入口迁移、空/错/离线态和键盘路径。命令面板、编辑器技术选型、导航在各窗口尺寸的最终行为、灵感球默认值与高级工作面需要原型和用户任务走查后定案。
- **尺寸和无障碍**：桌面测 880×640 最小窗、1040×760 默认窗、1280×800 小笔记本和 1440px 宽屏；Web/移动方案补 390px 级别窄屏与平板横竖屏。浅深两色、200% 文本缩放、真实焦点与读屏、中文输入法和减少动态效果分别检查；桌面冒烟以 ≥24px 目标作底线，不作为触屏验收标准。真实窗验证以 AX 树、文件和数据库为事实证据，截图用于核对布局和外观。
- **用户任务**：邀请未参与开发的用户独立完成快速记录、重启续写、导入后找回原件、库内提问核对出处、导出和恢复。记录操作路径、失败原因和是否能纠错；路线图建议 5–8 位首批用户试用两周。这是研究计划，自动化通过不能代替用户验证。
