# 产品功能、进度与交付路线

盘点日期：2026-11-12。基线为 `workbench/second-brain-validation` 的 `ca0858d` 与当时本地工作区。部分 R4、备份和 MCP 实现及其验收记录仍在本地改动中；这里的状态不代表 `main`、公开安装包或全部平台已具备同一能力。本次整理以代码、已记录的测试和验收为依据，没有重新运行历史验收。

## 产品要交付什么

KnowFlick 是本地优先的个人笔记与知识工作台。用户先记录与保留出处，再按主题或项目组织；需要时用这些资料学习、回答问题、回顾进度、写作，最后能把知识和原件带走。基础笔记、整理、全文搜索和数据出口不依赖账号、模型或网络。接入自己的模型和存储是选用项，标准产品不包含 KnowFlick 托管云订阅。项目主体延续 MIT 许可，模型、字体、代码、媒体及服务的第三方条件另核对。

| 产品层 | 用户动作 | 业务边界 |
| --- | --- | --- |
| 笔记 | 随手记、剪藏、导入、继续编辑、加附件、批注、整理收件箱 | 来源和原件独立保存；修订笔记不修改原文。同一原件可以被多篇笔记引用。 |
| 知识库 | 按主题或项目找笔记、做引用、审核提炼、维护有效性 | 笔记不必先转卡；同一笔记可属于多个范围；相似内容只建议核对，独立出处保留。 |
| 应用 | 问答、出卡学习、简报、复盘、目标、个人记忆、项目记忆、创作、外部工具接入 | 指定资料范围；事实、推测和生成草稿分开；引用回原文；写入、发送、对外访问各有明确授权。 |

首批试用对象是有多个项目的个人知识工作者。优先验证五条任务：随时记录、重启续写、按项目找回证据、据实复盘，以及将指定项目的资料交给外部工具。开发、研究、营销、自媒体等差异先由模板与范围承接，再根据试用决定是否开发专用应用。

### 适用平台与不在当前范围的事项

- **桌面**：Windows、macOS、Linux 用同一份 React/TypeScript 界面和 Tauri 宿主接缝；不能用一个平台的安装或通知结果推断另两个平台。
- **Android**：Kotlin/Compose 保留现有学习功能、系统分享、朗读、磨耳朵、学习地图、知识星图、局域网卡片同步和微件。新笔记协议、编辑和 Android 平板交互分批接入；当前卡片同步不等于 R3 新笔记同步。
- **浏览器**：现有体验用于访问部分能力和自动化验证。正式 Web 在 R5 单独验收持久化、文件权限、后台、模型和自建服务模式，不照搬桌面能力表。
- **暂不进入开发**：iOS/iPadOS 需要新的平台决定；已删的 Swift `apps/mac` 不恢复；Kotlin JVM `:desktop` 保持冻结，不加功能。预置知识库不恢复，历史 `seed` 值继续兼容。基础长文笔记已纳入范围；没有承诺还原 Word 的分页、复杂排版或专有格式。全库图谱、旧 `Entry`/wiki 模型、我方托管云和自动对外代发不计入当前交付。

## 如何判断现在做到哪一步

- **已实现**：在所列范围能查到实现或入口；**有限可用**：有可走通的子集，但来源、平台、故障或真实场景未覆盖。
- **已验收**：必须同时写明平台、数据类型与验证层级。单测、浏览器冒烟、macOS 隔离调试、QA release、标准配置 release、真实账号和真实用户试用分别记账。
- **待真实验收**：程序已有路径，仍需实机、真实服务、模型或人工标注；**规划**：有需求和验收条件，尚无足以交付的路径。现有 `PASS`、`SKIP` 与失败的详细记录以 [验收运行记录](../ACCEPTANCE_RUN.md) 为准。

## 推荐的下一轮顺序与依赖

以下是基于现有证据的实施建议，未指定日期、团队分工或服务采购。各批次的执行步骤与验证详见 [开发与验收](05-DELIVERY-AND-VALIDATION.md)；可并行补证的工作无需等待整个阶段结项。

| 顺序 | 工作包 | 依赖与验收产出 |
| --- | --- | --- |
| 1 | 保住本地闭环并收口恢复 | 延续 R0/R1/R4：用隔离资料验证老包、空目标、非空目标、冲突、缺附件、重复恢复与中断；补软删除素材/卡片/产物和非空邮箱/订阅。逐类对账与原生回执通过后再扩同步。 |
| 2 | 补齐设备证据和自动化覆盖 | Windows/Linux 安装升级、通知、包内 MCP 和物理录音；核对本机与 CI 冒烟清单。没有设备、账户或明确使用的资料时记录 `SKIP`，不阻塞纯本地笔记改进。 |
| 3 | 加强日常写作和可信找回 | 选高频来源（网页/文件，再扩会议与邮件）做真实链路；改进正文混排、引用和错误恢复。人工标注检索集，分别报告各来源、两字中文、过期、矛盾和无答案表现。 |
| 4 | 复盘、画像、创作与外部工具 | 补 R4 的真实模型、项目范围、原生交互和外部宿主证据。此批可与数据恢复、设备和来源验证并行。 |
| 5 | 安全启用多设备 | 先定稳定版本化笔记协议、设备与墓碑语义；在自建和实际用户的 WebDAV 服务上验证单向复制，再做双向。Android 先只读并保留未知块，之后开放编辑、离线队列和平板体验。 |
| 6 | 扩展高级功能和生态 | 从试用挑选 R5 批次。官方模块生命周期与权限经实跑后，再做第三方隔离运行时和生态。 |

重要的跨线依赖：R2 切片与引用依赖 R1 的稳定修订；R3 依赖备份、删除和冲突语义；R4 画像/创作和问答依赖原件与权限；R5 生态依赖已经过多次升级的模块接口。不能用一个 UI 开关替代对应执行层，也不能以归档包版本号替代备份覆盖率。

### 可量化的建议门槛

- **产品**：5–8 位目标用户、两周，观察独立记录、续写、找回、使用有出处的资料和恢复，记录成功率、耗时和放弃点。无默认私人笔记遥测；诊断由用户选择。
- **搜索与问答**：至少 100 条人工标注的中英混合问题，首 5 条正确来源命中率目标 ≥90%；个人资料关键事实有效支持引用目标 ≥95%；编造来源或越界引用为 0 容忍项。尚无本轮达标记录。
- **性能**：建议以 8 GB 内存、普通 SSD 的桌面及一台目标 Android 设备作参考，样本为 1 万篇笔记、10 万切片和有代表性的附件。在无大模型运行时，桌面可编辑首屏 ≤2 秒、键入 p95 ≤50 毫秒、全文搜索首批 p95 ≤300 毫秒；AI、转写和语义检索另测时间、峰值内存与能耗。这些是目标，不是现有跑分。
- **可靠性**：最后一次已确认保存不静默丢失；故障回执说明哪些数据已写入；同包重放不重复；关闭模块不留下对应后台任务；旧包缺字段不清空本机新数据。主线共享契约变化须过两套端的门禁。

仍待决定的事项：以哪台 Android 设备及哪种平板为参考、可用于验收的账号和模型/存储实例、首批支持的外部笔记格式、正式 Web 的持久化与自建服务形态、R5 首个扩展批次。旧优化清单中的 Android 状态拆分、性能热点、诊断、凭据存储迁移、更新与国际化可作为复核候选；旧 Swift 专用事项和旧日期不能当现行任务。无实际工作量和验收环境前不承诺具体日期。
