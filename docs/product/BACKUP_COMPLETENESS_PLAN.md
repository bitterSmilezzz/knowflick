# 备份范围缺口与后续实现

状态：桌面 v1–v11 与浏览器 v12 都是**部分备份**，不是数据库的完整快照。浏览器 v12 是独立能力分支，包含最近搜索历史但不声称有桌面 v5–v11 数据；v1–v11 客户端会拒绝 v12。桌面 v11 在 v10 前置快照齐全、回收站数据及其引用均通过验证时，增加软删除素材、卡片和产物；素材与卡片的删除时间随包迁移，恢复始终保持删除态，重复恢复幂等，同 ID 内容或删除时间冲突会在一个数据库事务内拒绝回收站批次。只有 v11 确实收录的已删除邮件来源素材才不再列为缺失原件。桌面 v10 在 v9 的邮箱、订阅、笔记历史和逐次复习前置快照均可用时，增加搜索历史；v9 在同样前置条件下增加逐次复习事件、项目归属及覆盖起点。旧累计次数不回填，复习历史按稳定事件 ID 幂等合并；搜索历史保留本机顺序，只追加未重复词条并报告重复或超出 8 条上限的条目。搜索历史与附件、设置从数据库外单独读取，不能保证与 SQLite 处于同一事务。v8 增加邮箱账号白名单配置、UID 游标、历史同步状态、已导入/隔离记录和断开账号遗留的去重记录；账号密码及可能回显服务器内容的错误文本不入包。邮箱地址、用户名、服务器、文件夹和邮件标识可能包含私人信息；恢复后需重新输入密码，启用的自动同步可能联网。每条邮件去重记录绑定其来源素材的有效、已删除或缺失状态及完整导出素材记录的 SHA-256 指纹；有效素材必须在包内，恢复前与写入时都会检查冲突。v7 增加订阅记录；地址含查询参数、片段或账号密码，以及不支持的类型不会入包，遗漏数量写入清单和回执。订阅名称、地址路径仍可能包含私人信息；恢复后启用的订阅可能自动联网。v6 起采集笔记历史及历史引用的附件；项目、目标和画像可安全采集时也随包带走，否则清单和回执说明缺失。笔记及其实际历史逐篇在事务内恢复，历史冲突不覆盖本地；旧包缺少历史时仍只创建基线。桌面恢复各版本包的素材、卡片和产物时，同 ID 的不同记录或本地删除态不会被覆盖，相同记录可重复恢复并报告跳过。浏览器恢复素材、卡片也会保留不同的本地记录；浏览器多标签之间的并发写入尚无事务保障。关联原件恢复后在单一事务中追加 R4 数据；同 ID 冲突或原件不一致会回滚这部分并报告已完成的其他写入。整体恢复不是单一事务，设置仍会替换。浏览器不能恢复 v5–v11，v12 浏览器分支只增加最近搜索历史。v4 为附件增加 SHA-256；旧 v1–v3 包继续读取，无附件字节校验的旧包会在恢复回执说明。旧版工作台不能恢复 v4–v12。校验和用于发现损坏，不提供来源认证。

浏览器创作台已可保存草稿到产物库；浏览器备份采集 `artifacts.json`，v1–v4 基础备份可恢复产物。重复恢复相同 ID 和内容会跳过，内容冲突时保留本地版本；产物存储损坏会在备份回执中作为缺口报告。该能力复用现有产物文件，不改变归档格式。浏览器多标签并发写入仍无事务保障。

笔记的删除态随 `notes.json` 中的笔记记录迁移；v11 的 `deleted_records.json` 数量统计与原子恢复事务专指软删除素材、卡片和产物，不包含笔记。2026-11-06 标准配置 release bundle 的合成软删除笔记原生恢复与幂等重放记录为通过；这不代表真实用户资料或 `deleted_records.json` 三类数据均已验收。2026-11-07 另一次标准标识 bundle 启动发现进程继承默认 `HOME`，启动时可能读取默认库；发现后在任何写入前退出。只对默认库精确查询合成简报标题，未找到匹配项，未扫描其它个人记录；该启动不作为隔离 HOME 证据，也不据此推断或追溯替换此前独立记录的结果。详见 [验收运行记录](ACCEPTANCE_RUN.md)。

## 已确认的缺口

对照 `systemBackup.ts` 的文件清单、`backupCollect.ts` 的采集入口和 SQLite 建表语句：

- v4 和浏览器备份不含项目、目标和画像；桌面端引用的已删除原件不能随包迁移时 v6 不含这些数据，并在回执说明。
- v1–v5 和浏览器备份不含完整笔记历史；v6 只保存源库实际存在的修订，不补造过去缺失的历史。
- v1–v6 和浏览器备份不含订阅；v7 不含地址带参数或格式不支持的订阅。
- 邮箱密码与上次错误文本不迁移；缺失来源素材只保留状态和指纹。v11 会另行携带已软删除的素材、卡片和产物；邮箱去重记录与同包删除原件的指纹必须一致。桌面 v10 前置快照齐全时会携带桌面搜索历史；浏览器 v12 用独立文件采集和合并浏览器最近搜索词。浏览器邮箱、订阅、逐次复习历史和桌面回收站没有采集与恢复链路。浏览器活动产物已纳入 v1–v4 基础备份。
- v1–v8 没有逐次复习历史；v9–v11 且所有前置快照可用时才携带事件。历史覆盖起点前不能还原具体评分，项目归属不完整的事件不能精确进入项目复盘；浏览器尚无逐次事件记录与恢复。
- MCP 授权及凭据不随包迁移；恢复后需要重新创建连接。向量、全文索引和切片属于可重建派生数据，但恢复后必须有可验证的重建路径。
- API 密钥、WebDAV 密码和邮箱凭据不应被静默打包。若未来支持密钥迁移，必须明确选择、加密及独立验证。
- v1 旧包可能还没有笔记、知识库及附件。备份前对草稿和附件的单项失败报告仍然有效，但不能弥补格式本身的缺口。

## 完整备份的实施约束

1. 先为每类权威数据定义版本化文件、字段和范围清单；新版本必须声明每类数据的覆盖状态和数量，逐文件校验、严格验证结构和引用。旧包按其版本解释，不把缺少的段落当成空集合去覆盖现有数据。旧客户端遇到新版本应明确拒绝，不能静默丢字段。
2. 导出以数据库一致性快照读取项目、目标、画像及其关联与删除标记；与附件和设置的跨存储边界必须报告可检测的并发变化或缺口。不能把内存视图、分页上限或缓存当全量。
3. 恢复前验证所有文件和关系，明确新增、合并、冲突、跳过和失败；以可重试的稳定 ID 保证幂等。冲突或引用缺失不得静默覆盖；阻止画像同源重建的标记、删除标记和历史修订必须一起保留。数据库变更在适当事务中提交，附件与数据库不是同一事务时要记录可恢复的部分结果。
4. 恢复到空目录及非空目录均须实测：新旧包、重复恢复、同 ID 冲突、篡改、附件缺失、中途失败、同步记录和跨端读取分别验证；按真实副作用报告，不将可重建索引和不迁移凭据误称为已恢复。
5. 逐次复习事件按稳定 UUID v4 记录；卡片排程更新与事件插入同一事务，跨设备恢复按 ID 幂等并在冲突时回滚事件批次。`coverageStartedAt` 表明真实历史的起点，旧卡片只含累计数与最近一次时间，不得伪造逐次事件或将不完整历史称为全量统计。真实桌面空/非空目录恢复验收仍待完成。

## 逐次复习事件契约（R4/D09）

- 一次用户评分对应一条不可变 `ReviewEvent`：调用方在写入前生成 UUID v4，记录卡片 ID、评分时间、`again / hard / good / easy`、`sm2 / fsrs` 算法，以及评分当时可确认的项目 ID 列表。项目索引不可用时仍记录复习，但标记项目归属不完整。
- 更新卡片的排程状态、累计次数与插入事件必须在同一 SQLite IMMEDIATE 事务提交。事件 ID 和内容相同的重试幂等跳过；同 ID 不同内容拒绝整次写入。浏览器体验若启用同一能力，使用单次 localStorage 写入保存卡片和事件。
- 事件保留稳定 ID，不设卡片外键；删除卡片不会抹掉已发生的复习事实，恢复事件也不会复活卡片。事件按 ID 并集迁移，重复事件跳过，ID 冲突使事件批次整体回滚。合并只迁移历史，不从事件重算两端当前排程状态。
- `coverageStartedAt` 标记本库开始真实记录逐次事件的时间。迁移前的 `reviewCount` 与 `lastReviewedAt` 只能作为卡片累计状态，不能生成伪造事件。复盘周期起点早于该时间时只能标注“已有事件记录，历史不完整”；完整覆盖后的周期才可称为周期总次数。多库合并后覆盖起点取较晚值，避免高估历史完整度。
- v9 `review_history.json` 以 SHA-256 校验，包含覆盖起点、全部事件、项目归属完整性及事件数量；桌面快照与其它 SQLite 数据在同一只读事务采集。只有笔记历史、订阅、邮箱快照均可用才生成 v9。恢复先严格验证，再在单一事务中按事件 ID 合并。旧 v1–v8 包没有这份历史，恢复后仍显示原有覆盖起点，不以空数组覆盖本地事件。

逐次复习事件路径已实现并通过自动化测试，但目录复制和 WebDAV 仍只能称为**部分备份**；服务端收到文件不等于内容可完整恢复。真实桌面空/非空目录、跨设备合并以及跨平台和外部服务仍需分别验收。

恢复附件时保留包内库相对路径，笔记正文因此仍能找到原件；相同路径、相同字节可重复恢复，不同字节不覆盖。附件缺失、冲突或路径不能原样恢复时，引用它的笔记及其知识库成员关系会跳过并列入失败回执。文件与数据库仍不是一个事务：部分失败可能留下已恢复的附件，需按回执检查；系统和文件存储不支持安全硬链接时会拒绝放置附件。自动化覆盖空目录的笔记、附件与项目关联往返；安装版及其他平台仍待真机验收。

桌面采集不会把格式损坏的卡片链接、标签或前置知识，以及笔记标签静默转换为空：这些错误会中止备份；产物来源清单损坏时则生成不含产物的部分备份并报告。恢复比较本地卡片和产物时同样拒绝损坏字段，不把它们当成空列表后误报相同。普通界面读取的容错行为不因此改变。

## 项目、目标和画像快照底座

`apps/workbench/src-tauri/src/backup_r4.rs` 提供六张 R4 权威表的一致性读取及单事务追加恢复：原样相同的主键可重复恢复，不同内容冲突、未知表/字段、版本不支持、缺失项目成员笔记或笔记内容不匹配都会中止并回滚；保留封存、目标证据和画像否认标记，不含 MCP 授权。测试覆盖新库往返、重复恢复、关联缺失、笔记同 ID 不同内容、重复主键冲突、无效字段及未来版本。

桌面备份采集采用单次 SQLite 只读事务，同时读取现有包的数据、笔记历史和 R4 快照；并发 WAL 写入测试验证同一事务看到一致数据。R4 采集失败或依赖无法随包携带的已删除原件时，v6 仍保存可用的笔记历史并报告 R4 缺口。附件和设置仍在事务外单独读取。项目成员和目标证据绑定原件指纹及缺失状态。画像证据只有无类型来源 ID，快照分别记录该 ID 在笔记、素材、卡片三类本地记录中的内容指纹和缺失状态，恢复时逐一核对；不能据此推断其他外部命名空间的身份。表结构与字段采用固定白名单，数据库增列时拒绝读写而不是静默导出。真实桌面目录往返及跨平台验收仍待完成。

## 邮箱迁移已实现与剩余边界

v8 的 `mail.json` 与主数据在同一 SQLite 只读事务读取。账号配置有显式字段白名单；出现未知账号配置字段或邮箱表结构变化时，整段邮箱快照失败并在回执说明。账号错误文本、密码文件不进入包。已删除账号留下的导入、拒收及同步状态仍会一起迁移。导入素材绑定覆盖有效、已删除和缺失三态：有效素材还会对照 `materials.json` 的内容指纹；目标库已有同 ID 的不同素材、账号、游标或去重记录会在预检/事务中拒绝，重复恢复按原记录幂等跳过。存在其它恢复失败时不会恢复邮箱游标。

已验证：`backup_mail.rs` 覆盖白名单、schema 漂移拒绝、同事务快照、完整记录往返、密码字段不入包、缺失/已删除素材状态、目标素材/去重冲突及重复恢复；前端覆盖 v8 文件/哈希/数量/素材指纹校验和有先前写入失败时不迁移邮箱状态。仍须在真实桌面库验证清空目录与非空目录恢复，并实测恢复后重新录入密码、账号身份变化和 UIDVALIDITY 改变时的实际同步行为。邮件导入素材已软删或缺失时，包保留去重状态和指纹而不恢复其正文；这是有回执的部分备份，不是原件恢复。

## 逐次复习历史已实现与剩余边界

每次桌面评分以 SQLite IMMEDIATE 事务同时更新卡片排程并插入事件；稳定事件 ID 重试幂等，事件插入失败会回滚卡片变更。备份快照在同一只读事务读取事件与其余数据库数据；v9 在笔记历史、订阅和邮箱快照均可用时带入覆盖起点及完整事件列表。恢复先校验事件清单，再在单一事务中按 ID 合并；冲突会回滚整个事件批次。复盘按日/周/月展示事件，只在周期起点不早于覆盖起点时标记周期历史完整；旧 `reviewCount` 不会补造历史。

已验证：`review_history.rs` 覆盖事务原子性、稳定 ID 重试、重复恢复、冲突批次回滚和覆盖起点合并；备份 WAL 测试确认并发提交的事件不会混入快照；前端覆盖 v9 文件/校验和/事件数量、旧版包无历史字段、重复 ID 拒绝和恢复计数。2026-11-07 在两个独立的 macOS QA release bundle 数据根之间用原生界面完成 v11 复习历史往返：一条评分事件和卡片累计状态恢复成功，同包重放按事件 ID 跳过且未重复计数。目标库覆盖起点按源、目标两端较晚值合并；因此可能晚于迁入事件，保持历史完整度判断保守。此项证明本机隔离目录往返，不代表 Windows/Linux 或真实设备间验收。

## 搜索历史备份（v10）

桌面端只有在笔记历史、订阅、邮箱和逐次复习快照均可用时才读取 `search_history.json` 侧车；此前置不全时不读取、不写入包，并在回执说明。严格验证只接受最多 8 条非空、首尾无空格且不重复的字符串。清单保存条数，文件使用 SHA-256 校验；缺文件、篡改、重复项、超限或条数不符都会在任何恢复写入前拒绝整包。浏览器体验明确不支持这份桌面侧车。

恢复时先严格读取本机历史，损坏时保留原文件并报告，不以空列表覆盖；有效时保留本机 LRU 顺序，再追加备份中的新词。已存在和因容量上限未能追加的词条都计入“跳过”。旧版包没有该字段，因此不会触碰本机搜索历史。错误回执不携带搜索词内容。该侧车和附件、设置不在 SQLite 只读事务中，v10 仍是部分备份。

自动化覆盖格式严格校验、前置快照门控、SHA-256/数量对账、损坏拒绝、恢复合并计数及本机损坏保护。v10 增量实施时的 2026-11-01 门禁记录为前端 648 项、Rust 179 项通过（3 项忽略）、18 套浏览器冒烟通过；v11 最新门禁见下节。安装版空目录/非空目录恢复和跨设备人工验收仍待完成。

## 浏览器最近搜索备份（v12）

主搜索框在用户提交查询或离开搜索框时记录最多 8 条最近搜索；用户可重用单条记录、删除一条或清空全部。桌面历史继续写入 `search_history.json` 侧车，浏览器历史写入独立的 localStorage 项；两端都只在本机保存，不随搜索请求发送。备份前严格校验格式、重复项和数量。

浏览器 v12 使用 `profile: "browser"` 和 `browser_search_history.json`。这是 v4 基础备份的独立扩展分支，不包含桌面 v5–v11 数据。清单和文件使用 SHA-256，搜索词数量与文件逐项对账；缺文件、篡改、格式错误、重复词或超限都会在任何恢复写入前拒绝整包。恢复先严格读取本机历史，损坏时不覆盖；成功时保留本机顺序，再追加备份中的新词。旧 v1–v11 客户端会因未知版本拒绝 v12。

自动化覆盖最近搜索写入、重载后读取、浏览器 v12 包生成与校验、恢复合并路径及旧客户端版本拒绝。`settings_plugins_smoke.mjs` 还实际点击设置页导出/恢复，从生成的 ZIP 往返验证本机顺序保留和备份词追加。浏览器多标签并发写入仍无事务保障，搜索历史、设置和附件也不与浏览器主数据处在同一事务中。

## 桌面回收站备份（v11）

桌面 v11 在笔记历史、订阅、邮箱、逐次复习、搜索历史和 SQLite 回收站快照均可用时，增加 `deleted_records.json`。回收站快照与活动素材、卡片、笔记、产物及 R4 表在同一只读 SQLite 事务中采集；附件仍在事务外单独读取。软删除素材和卡片保留删除时间，产物保留删除标记。卡片来源必须能在同一备份中找到活动或删除态素材；无法安全携带时降为 v10 并在回执说明。
