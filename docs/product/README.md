# KnowFlick 产品重规划

规划日期：2026-10-24。状态：**需求基线与建议方案 v1，尚未全部实现**。

这份规划承接本次产品所有者的完整诉求，保留已有需求与能力。分期表示交付顺序，不表示删除后期需求。文中的界面、指标、模块边界和技术增补是建议；代码现状以仓库与验收证据为准。

## 产品定义

**KnowFlick 是以本地数据为基础、可按需扩展的个人笔记与知识工作台：把生活和工作中的记录，变成找得回、用得上、能带走的个人知识。**

产品有三层：

1. **笔记**：接住原始信息，并让用户持续书写、批注、整理。闪念、长文、网页、邮件、会议、手写、录音和文件都能成为笔记，保留出处与原件。
2. **知识库**：把笔记、选段和用户确认的提炼组织成主题与项目。提供索引、关联、出处、去重建议和持续更新。它不是只存 AI 摘要的仓库。
3. **应用**：使用指定知识完成问答、学习、复盘、目标回顾、项目记忆和内容创作，并向其他工具提供授权范围内的材料。

这三个层次是产品职责，不要求用户把每条内容手工搬三次。保存笔记后即能全文搜索；满足范围规则的内容可以自动进入知识库视图。AI 提炼可选，未经提炼的原文仍能被检索和引用。

一条录音可以同时属于「工作周报」和「项目 A」；媒体字节只保存一份。项目总结可以引用邮件、会议和笔记；收藏十篇同主题文章不等于这个人认同了文章中的十个观点。

## 本次明确的约束

- 需求不减：既有剪藏、导入、AI 出卡、刷卡、卡库详情、收藏、历史、测验、统计、导出继续可达；Android 已有朗读、磨耳朵、学习地图、微件等能力不因桌面改版消失。
- 笔记本身是完整工作对象，支持持续写作；不能强迫所有内容先变成知识卡。
- 桌面、手机、平板分别设计交互；首层简洁，扩展能力逐层呈现。
- 本地基础功能无需账号、网络或模型密钥。AI 的离线程度由实际启用的模型决定。
- 标准产品不包含我方托管云订阅；提供用户自选、自建存储的接入能力。
- 保持本项目 MIT 许可；第三方代码、模型、字体及服务各自核查许可，MIT 不意味着可以随意复制其他软件。
- 功能模块可关闭；大模型与重解析器按需安装。完整能力目录不等于默认安装全部组件。
- 个人画像用于帮助用户理解自己，须可查看、纠正、关闭、删除并控制对外使用范围。
- 知识可供 MCP、适配的 AI 技能包及其他软件使用；导出、脱离本产品恢复数据是基础能力。

## 规划的第一批用户与主场景

建议先服务**独立知识工作者**：有多个工作或学习项目，每天在电脑处理资料、在手机捕捉信息，需要把零散记录用于工作和生活。这是首批验证对象，不限制未来服务营销、研究、创作或其他行业。

日常主场景：

1. 临时想到一点，快捷键或手机分享即可保存；暂不分类也不会丢。
2. 写一篇笔记，把网页、文件、图片和录音放到同一上下文；重启后继续写。
3. 准备处理项目 A，在项目知识库内找回之前的结论与证据。
4. 周末回顾本周记录，区分事实、待办、想法和 AI 建议；用户确认后再记录目标变化。
5. 在外部开发或创作工具中，只读取为该项目授权的知识。

第一阶段不试图让所有行业拥有独立产品流程。行业差异先通过模板、知识范围和应用预设承接，再用真实使用决定是否值得做独立模块。

## 当前有哪些基础

盘点基线：`bfbae20`，2026-10-24。本轮检查源代码与既有验收记录，**没有重新运行全产品或宣称这些功能已经达到新规划标准**。

- `apps/workbench/src/ui/workspace/Workspace.tsx` 已有收件箱、知识库、邮箱、订阅、问答、简报、产物、统计、测验与复习入口；目前来源入口仍占主导航，记录方式在侧栏展开。
- `src/ui/workspace/model.ts` 将内容分成 `material | card`，尚无独立的可持续编辑笔记与修订模型。素材和卡片可以关联，但不能等同于完整笔记系统。
- `src-tauri/src/db.rs` 已有素材、卡片、产物、全文索引及卡片向量；无需推倒重做 SQLite、桌面壳或学习算法。
- `NotePads.tsx`、`ink.ts`、`media.rs` 已有手写和录音基础。现有文档明确：手写没有 OCR、压感和橡皮擦；真实麦克风及桌面保存尚需完整验收。
- `mail.rs` 已有只读 IMAP over TLS，当前只实现 LOGIN；服务商预设不能证明 Gmail、Outlook、QQ、163 都连接成功，尤其 OAuth 是独立缺口。
- `embeddingEngine.ts` 已有远程、本地模型及字符特征哈希回退；哈希回退不能作为“理解同义语义”的质量承诺。当前向量表按维度识别失配，没有完整模型身份。
- `tools/mcp-server.mjs` 已能检索、读素材并写入卡片/素材；当前已有写能力，**本规划的默认只读与项目授权是待改造目标**。
- `.kfbackup` 已支持内容与媒体往返；现有校验为 FNV，需要在新版本规划中升级并保留旧包兼容。
- 仓库 `LICENSE` 为 MIT。桌面继续一份 React/Tauri，Android 保持 Kotlin/Compose，不恢复已删的 Swift 端。

重要验收缺口见 [FIRST_VERSION_ACCEPTANCE](../FIRST_VERSION_ACCEPTANCE.md)：真实模型质量、真实邮箱、真实桌面录音与 Windows/Linux 安装首启。CI 通过或有按钮均不能替代这些证据。

## 怎么做到功能多、默认轻

**基础内核**始终提供：笔记、来源与附件、组织、全文搜索、知识库范围、基础引用、导入导出、备份恢复。

**官方可选模块**按用途打开：学习、邮件、订阅、OCR、语音/会议、本地 AI、知识问答、复盘、同步连接器、外部工具接入。已有学习用户升级时保留启用状态、入口与数据；首次安装只展示选用引导。

**第三方扩展**后期开放：专有笔记格式、细分行业工作流、专用存储、定制应用。先把官方模块的生命周期和权限真正落实，再开放加载器；配置清单本身不代表沙箱已实现。

模块化不能让基础能力碎裂。例如关闭语音识别后仍能保存、回放录音；关闭 AI 后仍能查看笔记、搜索和编辑知识库；关闭学习模块后所有卡片与学习记录仍保留。

## 产品是否成立，用什么判断

建议以“**用户在一个真实任务中，成功找回并使用了有出处的个人知识**”作为核心结果，记录在本地统计，是否分享诊断由用户选择。单纯记录条数、AI 调用次数和安装量不足以证明价值。

邀请 5–8 位符合首批场景的用户试用两周，观察能否独立完成收集、续写、找回、使用和恢复；记录放弃点、纠错成本与失败原因。这是研究计划，不是已经获得的调研结果。不在未经同意时采集私人笔记做遥测。

最先改善的是持续写笔记与找回内容，再把来源和应用接得更全。完整愿景保留，发布按验证结果推进。
