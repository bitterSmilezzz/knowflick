# 本地数据、知识检索与 AI 方案

日期：2026-10-24。状态：建议架构，既有实现不在本轮迁移。外部事实与候选方案见 [官方资料研究](research/2026-10-24-local-knowledge-and-ai.md)。

## 三层产品与存储不是同一件事

用户看到“笔记 → 知识库 → 应用”。内部保留出处、笔记、修订、附件、引用、派生内容、学习状态等实体；不能为了凑三层，把整篇笔记压成一张卡片。

建议逐步补充以下模型，不把所有新字段塞进 `materials.metadata_json`：

- **Source / SourceSnapshot**：来源身份与某次原始快照。网页 URL、邮箱账号内的稳定 id、导入文件与抓取时间属于这里。外部内容更新产生新快照。
- **Note / NoteRevision**：用户可持续编辑的笔记及其修订。正文采用有版本的块文档，支持文字与附件引用；导出 Markdown 时携带块标识和非 Markdown 内容的旁车文件。
- **Blob / AttachmentRef**：按内容指纹寻址的原始字节与引用。多笔记共享 Blob，但标题、来源、标注和权限各自独立。
- **KnowledgeBase / Membership**：知识库的范围、说明、规则与成员关系。多个库引用同一笔记，不复制正文。
- **Citation / Extract**：选段与提炼；定位到笔记修订、页码、块或音视频时间点。知识卡继续是可复习的提炼形式，不成为唯一知识类型。
- **Artifact**：问答、纪要、复盘、草稿；记录任务、范围、使用的来源版本和生成信息。
- **ProfileClaim / Goal / ProjectContext**：有证据、作用域、确认状态和有效期的个人记忆，以及用户明确设定的目标。
- **Job / Change / Tombstone**：可恢复的后台任务、同步变化和删除记录。

“收件箱”是笔记的处理状态，“知识库”是组织与使用范围，“应用”是任务流程；三者都不应触发复制一份相同媒体。

## 权威数据和可丢弃数据

建议布局如下，具体目录名在迁移实现时版本化确定：

```text
library/
  library.db          笔记、修订、来源、关系、确认结果、学习状态
  blobs/sha256/...    原件与用户附件，内容寻址
  indexes/            全文/向量等可重建索引，可逐步从现库移出
  cache/              缩略图、临时解析等，有配额
  exports/            用户主动创建的导出，非日常第二真相源
models/               按需安装的模型，重装后可重新下载
credentials/          独立凭据，不进入内容导出与普通同步
```

SQLite 是笔记及元数据的权威来源，Blob 是附件字节的权威来源。Markdown 是开放导出，不同时运行一个会双向覆盖数据库的“实时镜像”。未来文件夹编辑模式若要成为独立真相源，需单独设计冲突和转换契约。

原始 OCR/转写属于可重建结果；用户校正或确认过的文本进入笔记修订，作为长期资产纳入同步与备份，清缓存时不能被一起删除，也不能被重新识别结果覆盖。

开始可沿用现有 `knowflick.db`，分步迁移新表和索引。是否拆出独立索引数据库是可替换的实现选择，必须用写入、重建和恢复实测决定；基础设计先保证索引逻辑上可重建。

保存顺序：附件写暂存文件 → 完整性校验 → 原子改名 → 数据事务建立引用 → 投递索引任务。异常留下的未引用 Blob 延后清理，不能先删除附件再期待数据库提交成功。

编辑写入必须带修订/内容版本校验，防止来自另一窗口、MCP 或同步的旧草稿覆盖新内容。索引任务携带目标修订号，完成时再次确认版本；过期任务不写回当前索引。

## 原件保留与容量

- 用户手写、拍摄、录制或主动导入的唯一原件，默认保留；不能在尚未备份时因“已经转写”而自动删除。
- 网页保存选中的内容、来源和快照信息；整站离线资源包是可选成本。失去原站时仍可读已存正文。
- 外部大型视频可选“仅引用”“保留字幕/笔记”“下载原件”。选择前显示差异，引用模式明确不保证原站失效后可回放。
- 缩略图、临时音频转换、向量和模型分别统计。可安全重建的数据先清理，永久内容经预览与明确操作再删。
- 多引用 Blob 要在引用计数、回收站保留期、同步墓碑与备份策略满足后才回收。引用计数是缓存，清理前校验真实引用。

## 去重：节省空间与保留意义

1. **字节完全相同**：以 SHA-256 + 字节长度标识附件，必要时比对字节；物理共享，逻辑来源不合并。
2. **同一来源同一版本**：连接器稳定键避免重入；网页 URL 正规化只能去安全的追踪参数，不能删掉决定内容的参数。邮箱须保留服务商/文件夹/UIDVALIDITY 等身份边界。
3. **同一来源内容改变**：新修订，而非当成重复丢弃。标注对某一历史版本的引用仍可读。
4. **文字近似**：规范化指纹用于候选，保留原始文字；显示差异再由用户决定。
5. **语义近似**：只建议，不自动删除；两个相似观点可能时间、立场或项目不同。

现有 `contentHash.ts` 的 FNV-1a 与图片“文件名+大小”只属于旧去重提示，不能成为原件唯一身份或强完整性保证。新旧指纹并存迁移，旧数据验证后补新指纹，不在启动时一次阻塞全库。

## RAG 应该放在哪里

RAG 是“使用知识时找证据再生成”的一条处理链，不是全部知识库，也不是存储格式。没有模型，仍有笔记、知识库和全文搜索。

建议流程：

```text
保存笔记/原件 → 提取可检索文本 → 按结构切片 → 建立全文/可选向量索引
用户选择范围 → 先限制允许的内容 → 多路召回 → 融合/可选重排
→ 组装含出处的上下文 → 生成 → 校验引用 → 显示与可选保存
```

默认全文索引覆盖笔记与原件提取文本，不只覆盖卡片。语义索引覆盖有必要的段落，不把整篇长文压成一个向量，也不为每次产物重复向量化全部原文。

切片优先按标题/段落、表格边界、页码和说话时间分段；起点可试 400–800 tokens、少量重叠，**这是实验参数，需中英混合、代码、表格、邮件与会议语料验证**。保留父文档与邻段扩展，禁止切片后无法回原件。

初期沿用 SQLite FTS5、现有向量扫描与 RRF；中文短词、拼音/首字母、专有名词、精确数字与代码都要进入查询集。重排模型为按需模块；ANN 或其他引擎仅在真实规模瓶颈出现后引入。

不能用一个维度数代表向量空间。索引记录至少包括：`provider/model/revision/dimension/normalization/chunker_version/content_revision`；同维度不同模型也不混算。切换模型创建新索引版本，后台构建完成后切换；索引未齐时显示覆盖率并允许全文检索。

外部向量模型和生成模型分别配置。现有优先远程的策略须增加“仅本地”模式；本地失败不能静默回退到外部服务。字符特征哈希可做词面相似候选，不标为真正语义理解。

## 回答质量与更新

每条涉及私人知识的具体断言关联原文引用；引用定位不能只靠模型写出一个看起来正确的编号。服务端验证 id、范围和版本，越权或不存在的来源不给正文。模型若无法确定来源，应降为无出处建议或明确资料不足。

原文修改/删除后，索引、提炼、产物、画像与外部导出都要可追踪依赖：索引重建，旧产物标记过期；用户确认过的结论提示复核，而非静默改写。彻底删除时清理可识别派生项与缓存，并说明已导出的文件和第三方已接收内容无法自动收回。

删除后自动化测试验证不能继续搜到、问到或通过 MCP 读到。离线设备与备份的保留规则单列说明，避免承诺瞬时全世界消失。

## 画像：可管理的个人记忆

画像分三类：用户明确填写/确认的事实；基于明确动作的统计；AI 提出的待确认推测。收藏不等于认同，阅读某职业内容不等于从事该职业，一周没有记录不等于没有工作。

每条记忆包括内容、证据、类别、项目/全局范围、建立时间、最近确认、有效期、状态。用户可以查看证据、修改、否认、暂停和删除；删除应生成阻止同源旧证据自动重建的标记，用户重新允许后才学习。

私密笔记可排除于全局检索、外部模型、画像和 MCP；这些用途可分别控制。范围过滤发生在召回与打分前，并再次检查输出，不能只在界面隐藏。

建议先做用户确认的工作风格、当前项目与目标，不追求一个不可解释的“人生评分”。建议是待选择方案，目标完成必须对照用户设定条件与记录证据。

## 本地、同步和加密分别是什么

本地保存不等于静态加密；本地模型不等于同步 E2EE；HTTPS 不等于存储服务读不到内容。界面分别显示设备存储、模型调用与同步目的地。

建议先提供自选目录的版本化完整备份，再做 WebDAV、S3 兼容等存储适配。Nextcloud 等可通过相应协议接入，但需独立认证/限流/冲突验收；云盘“能上传一个 ZIP”不等于实现双向同步。

**禁止多个设备同步打开同一份活 SQLite 文件**。每设备维护自己的库，传输不可变 Blob、逻辑变化批次和墓碑；笔记正文先提供可见的冲突副本，后续确有协作需求再评估 CRDT。不用设备墙上时间的最后写入直接覆盖长文。

同步考虑断线、重复投递、乱序、部分上传、恢复、设备遗失、密钥轮换、存储配额与旧客户端；有版本与校验，不能完成一半显示成功。附件懒下载，但引用可见。

可选 E2EE 在上传前加密内容与附件；密钥恢复、设备授权和服务端可见元数据要写清楚。忘记密钥不能承诺由项目方找回。静态数据库加密独立评估，不以应用密码窗冒充。

## 模块、插件与第三方开放

先模块化领域能力与运行资源：核心、连接器、解析器、AI 任务、应用。关闭模块不启动对应任务/模型，仍保留最小格式读取器。官方模块可以在进程内惰性加载，不要求每个小模块开独立常驻进程。

第三方代码后期使用受限接口与隔离运行时。独立进程不天然等于沙箱，必须落实文件、网络、数据库代理、配额、超时和崩溃恢复；未做完前不得宣称第三方安全隔离。

MCP 默认只暴露所选知识库的只读搜索和引用读取。当前已有写工具需要迁移为显式授权、可审计的能力；写入优先追加收件箱，不让模型任意覆盖笔记。不能把 UI 关闭开关当成 stdio 独立服务端的权限阻断，所有入口共享授权策略。

Skill 包提供指定项目的上下文索引、来源与使用规则，按具体工具格式适配；Skill 不等于万能协议，也不在打包时隐式携带全库。需要动态检索时指向受授权的 MCP 或本地 API。

## 迁移与恢复

迁移前创建一致性备份；旧素材映射到笔记/来源，旧卡片与 FSRS 字段保持原 id 和含义，新增关联表连接笔记；旧 `materialId` 在兼容出口继续有意义。不能重建卡片 id 后假称学习进度保留。

旧 `cards.json` 仍可交换学习子集；**它不是新笔记系统的全量同步协议**。新包必须版本化，携带笔记修订、原件、引用、知识库和产物关系。Android 先实现读取与保留未知字段，再开放对应写入。

新备份清单列对象大小、SHA-256、schema 与最低读取版本；兼容现有 FNV 旧包，提示其校验能力。恢复到全新目录验证引用、媒体、学习状态、知识库范围和数量，不覆盖用户现用库后才发现不兼容。重建索引与重新下载模型不影响恢复结果完整性。
