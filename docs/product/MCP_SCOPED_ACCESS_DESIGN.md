# MCP 项目范围授权：首批纵向实现设计

状态：**待实现、待验证的设计**；本文件不是功能发布或安全认证记录。依据
[实施路线 R4](DELIVERY_ROADMAP.md)、[本地数据与 AI 架构](LOCAL_DATA_AND_AI.md)
和 [能力目录 E06](CAPABILITIES.md)。目标是让用户为每个外部连接选择一个项目，
在本机经 MCP 只读检索该项目的有效笔记，并能撤销单个连接；后续再逐项恢复和
扩展已存在的外部能力。

## 现状与交付边界

- `tools/mcp-server.mjs` 是设置页生成配置所指向的独立 stdio 进程。现在它默认
  允许全库读取，写工具由环境变量授权，模块总开关从 `settings.json` 读取；
  `search_knowledge`、`search_materials`、统计、简报、集合资源与素材单条资源
  都可能暴露全库信息。模块设置不存在或解析失败时当前会放行。
- `src/domain/mcpServer.ts` 的 `handleMcpRequest` 是另一份协议处理代码；仓库中
  未发现生产调用点，其测试仍覆盖全库读取和回调写入。它不是已验证的对外宿主，
  也不与独立进程共享项目授权。
- 项目成员 `project_members` 和知识库成员 `kb_membership` 指向笔记，不直接限定
  素材、卡片、简报或统计。不能用项目成员过滤现有素材结果后宣称全工具已隔离。
- 首批范围是**一个连接、一个未封存项目、只读项目成员笔记的标题和正文**；
  无默认全库授权、无个人画像、无附件字节、无素材/卡片/聚合信息、无写入。
  动态成员变更直接改变可读范围，不复制项目快照。

既有外部读取与写入能力要保留为后续可迁移能力。首批切换后旧配置不能继续使用，
旧工具在新授权下明确拒绝并说明迁移状态；不允许旧环境变量绕过授权。发版说明
必须指出这段兼容性中断、恢复路径及替代方式。后续按单独授权恢复写入收件箱与
建卡，并为素材、卡片及聚合定义可证明的范围关系；不能自动把项目笔记关联的素材
全文或卡片视为已授权。用户可继续在应用内使用既有功能。

## 授权契约与存储

每个客户端连接单独创建授权；客户端名称是用户填写的显示标签，**不是可验证的
客户端身份**。一个授权只绑定一个项目，授权不能由客户端请求参数切换项目。建议
在权威 SQLite 中新增 `mcp_grants`，使用与其他项目表相同的迁移机制：

| 字段 | 契约 |
| --- | --- |
| `id` | 随机、不可复用的授权标识，供界面管理与审计；不是凭据。 |
| `client_label` | 用户填写的显示名称，限制长度，按普通文本显示。 |
| `project_id` | 项目外键；创建时必须存在且未封存。缺失或封存时拒绝使用。 |
| `token_hash` | 由系统安全随机数生成的至少 256 位令牌的 SHA-256 摘要，唯一；只存摘要，不存明文。 |
| `created_at` / `revoked_at` | 毫秒时间戳；`revoked_at` 非空不可使用，重复撤销幂等。 |
| `policy_version` | 明确授权语义版本；未知版本拒绝，不按旧规则猜测。 |

生成令牌、写入授权记录是一次原子操作；生成失败不落记录。授权只允许由桌面
用户操作创建和撤销，MCP 无授权管理工具。令牌只在创建成功时返回并短暂展示，
后续不可再次读取；丢失时新建并撤销旧授权。传给 stdio 进程的配置使用环境变量
`KNOWFLICK_MCP_TOKEN`，不放在命令行参数、日志、错误消息或审计记录中。客户端
配置文件本身会保存明文，界面须提示用户妥善保管；剪贴板也可能保留副本。
不把令牌塞进静态 Skill 包。

授权记录与项目数据同库，不能将它当成可安全携带到另一设备的用户内容：应用的
备份导出不包含授权与审计表，恢复不会创建授权；若用户直接复制整个 SQLite 文件，
记录也会随库复制，不能声称自动失效。用户应在副本上撤销并重新签发；若将来支持
整库迁移，需设计明确的实例绑定和失效流程。迁移只新增表，不改变已有笔记、项目
和学习数据；旧库未升级、表缺失或策略版本未知时，服务端拒绝访问并提示先打开
新版桌面端完成迁移。

## 请求执行与拒绝策略

1. `initialize`、`ping` 只返回协议元信息，不返回用户数据。其他请求必须先检查
   模块启用状态、令牌格式、摘要匹配、授权未撤销、项目存在且未封存、策略版本。
   设置读取失败或格式无效时拒绝，不能因错误回退为启用。设置缺失的升级语义须
   通过显式迁移确定，不可把无法读取与已启用混为一谈。
2. 每次请求都检查权威状态，不能把启动时结果缓存到连接结束。非法、缺失、已撤销
   凭据统一返回不泄露授权细节的拒绝；配置损坏、数据库不可用应给用户可操作的
   错误，不回退到旧的全库逻辑。不得输出令牌或查询正文。
3. 在同一数据库事务内检查授权、成员关系、软删除状态并读取数据。授权与成员范围
   必须在搜索、排序和 `LIMIT` **之前**应用；任何输出前再次由同一范围约束保证。
   单条资源按项目成员关系和未删除条件查询；不存在与越权使用相同的不可访问响应，
   避免借 ID 推测项目外数据。当前授权下不应列出素材、卡片、简报、统计和画像。
4. 旧的 `KNOWFLICK_MCP_WRITE` / `KNOWFLICK_MCP_ALLOW` 不提供绕过入口；
   旧配置返回具体迁移提示，不能静默升格为全库。未知工具、资源、权限版本一律
   拒绝；空查询也只能列当前项目的有效笔记。
5. 完成中的请求按其事务开始时的授权快照处理。撤销、封存或移出成员提交后，
   **之后开始的请求**必须拒绝或不再返回相应笔记；已在途的请求可能完成，已返回
   和外部保存的内容无法收回。响应不得先于事务成功结束发出。

首批协议提供 `search_project_notes` 和 `knowflick://notes/{id}`：搜索返回范围内的
笔记 id、标题和命中摘录；读取返回标题、正文、修订号和来源 URI。读取字段列表是
白名单，不附带内部元数据、标签或附件。检索若使用 FTS，必须先在同一查询按
`project_members` 及 `notes.is_deleted = 0` 收窄再排序和截断；索引落后时不得输出
旧正文，必要时以当前 `notes` 为准回退。限制查询、返回条数与正文大小，并对截断
明确标注；不能把不可访问的原文塞进错误或调试信息。

### 两个入口的迁移

- **独立 stdio**：在 `tools/mcp-server.mjs` 的分发层统一调用授权检查，并将经验证
  的项目范围传入唯一的受限查询路径；`tools/list` 和 `resources/list` 只列已允许的
  能力。直接调用旧工具或旧资源也要拒绝，不能仅靠隐藏。工具、单条资源、集合、
  统计、简报、写入以及模块停用都纳入同一策略测试。
- **TypeScript 协议处理器**：在接入生产宿主之前默认拒绝数据与写入请求；测试
  覆盖无授权及旧回调不能绕过。未来宿主只能注入由可信授权层验证且可重新检查的
  范围与受限数据访问接口，不接受外部传入的项目 id 或预先全库数组作为授权依据。
  宿主真正存在后，必须以同一组策略反例验证两端，不能仅复用类型或文案就称策略
  统一。两实现语言不同，不得假设它们天然共享代码。

## 桌面设置与审计

设置页列出授权名称、项目、创建时间和状态，并提供**新建授权**与**撤销**。新建时
用户选未封存项目、填写名称，界面清楚列出允许读标题和正文、只读、成员变化会
改变范围；确认后只展示一次包含脚本路径、库目录与令牌的 MCP 配置，提供复制与
完成关闭。项目为空、已封存或数据库不可用时不可创建；浏览器模式如无法执行此
授权流程，明确说明需桌面端，不展示看似可用的全库配置。撤销针对单个授权，
显示成功或失败；已建立连接也在下一次请求检查撤销状态。已封存项目的授权显示
不可用，不因项目以后恢复而自动给出不可解释的访问承诺：如支持解封，需先明确
是否要求重新授权，并用测试固定所选规则。

审计只记录授权 id、时间、操作类型和结果，不记录令牌、查询、正文或完整 URI；
未识别凭据不记录其原文。设定有界保留策略，并在设置页说明。要使审计可靠，
允许的数据请求应在同一事务内完成授权检查、数据读取及审计记录，提交成功后
才返回内容；审计无法写入时拒绝该请求并提示故障。该选择意味着独立服务需要
数据库写权限，仅用于审计，业务内容仍是只读；需要评估并测试 SQLite 锁竞争。
失败记录及清理也不能无限增长；日志中不记录敏感载荷。

## 验收与实施顺序

1. 添加数据库迁移、授权创建/列表/撤销命令及纯策略边界；测试随机凭据不入库、
   旧库迁移、无效策略拒绝、撤销幂等及备份不导出授权。
2. 实现范围受限的查询与读取。构造 A、B 两个项目和相同关键词笔记：A 搜索、
   空查询、直接猜 B 的 URI 均不能泄漏 B；共享成员可按实际成员关系被双方读取；
   成员移除、笔记软删、项目封存即时改变后续请求。验证过滤发生在排序与截断前，
   以及正文更新后不返回旧索引内容。
3. 接入独立服务的所有入口与模块开关，验证缺失/伪造/撤销凭据、旧环境变量、
   旧资源、聚合、写入、损坏设置及不存在迁移均拒绝。使用同一进程长连接实测撤销
   和成员变化；覆盖在途事务边界、审计写入失败及数据库锁错误。
4. 完成设置页全流程及 TypeScript 处理器的默认拒绝；测试配置只展示一次、列表不
   泄露令牌、撤销单连接不影响另一连接、脚本使用实际安装路径和所选库。更新旧
   外部写入冒烟，记录明确中断和后续迁移，不保留旧的全库成功断言作为验收。
5. 运行 `./tools/verify_workbench.sh` 和相关 MCP 端到端冒烟；以真实客户端测试
   安装包连接、项目隔离和撤销，分别记录本机与跨平台的结果。未跑的真实客户端、
   Windows/Linux 测试标为待验，不从单元测试推断完成。

## 安全边界

这是产品进程对遵循该协议的客户端实施的**应用级范围控制**，不是操作系统沙箱。
stdio 子进程通常与客户端同属一个系统用户；能直接读取或修改库文件、设置或客户端
配置的本机程序可以绕过该层。用户给客户端的内容和静态副本不能通过撤销收回，
令牌也可能被有权访问客户端配置或运行环境的程序复制。跨用户、恶意同机进程、
加密存储及远程连接需另行设计与验证，不能由本批授权推导安全保证。
