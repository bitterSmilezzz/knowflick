# 界面收敛：四段主线（第一套桌面 / apps/workbench）

> 问题：界面把「来源」「库」「应用」摊在同一层，同类入口重复出现，读一封信要面对一整块操作区。
> 做法：按产品主线 **来源 → 收件箱 → 知识库 → 应用** 重排，把子筛选与动作折叠起来。
> 原则：**只改层级与暴露面，不删能力**。每个原有入口仍然可达。

## 一、改了什么

### 侧栏：从「9 行平铺 + 3 组混排」到「四段主线」

改之前，侧栏把四个阶段和子筛选混在一起，`订阅源` 甚至被归进「回顾」组——它明明是来源。

改之后：

```
来源      邮箱 · 订阅源 · （导入文件）
收件箱    收件箱
知识库    全部知识
          ▸ 筛选    （收藏 / 已归档，折叠）
          ▸ 分类    （最多 8 个，折叠）
应用      ▸ 应用       （知识问答 / 认知简报 / 产物库 / 统计 / 知识测验，折叠）
          温故复习    （每天都要用，不折叠）
```

- **一级入口从 9 个收敛到 6 个**（邮箱、订阅源、收件箱、全部知识、知识问答、认知简报；
  复习按插件开关出现）。
  > 2026-10-22 追加：新增「统计」「知识测验」后一度涨到 9，超了 6 的约定。
  > 现在「应用」段整体收进一个可折叠区（`summary` 兼作组标签），**当前在应用页时
  > 自动展开**；「温故复习」留在折叠区外——它是每天都要用的高频入口。
  > 于是**一级入口实际为 4 个**（邮箱、订阅源、收件箱、全部知识）。
- **收藏 / 已归档** 折叠进「筛选」——它们是库的筛选条件，不是并列目的地。
- **分类** 折叠，带计数。
- **导入文件** 改成来源段内的动作按钮（`.ws-nav-action`），不再计为一个目的地：它是动词，不是位置。
- 折叠项带三角指示与计数，展开态截图已核。

### 顶栏：去掉与侧栏重复的入口

顶栏原有「语音转写 / 导入文件 / 导出备份」，其中导入与侧栏来源段完全重复。现在只剩两个全局动作：

```
语音转写（本地 Whisper）   导出备份
```

### 空态：不再重复第三个「导入文件」

空库时原来侧栏、顶栏、空态三处都能导入。现在空态只给**用户还没看到的入口**：连接邮箱、添加订阅。

### 阅读区：整块操作区 → 一行入口

每条素材下面原本常驻一整块「从素材提炼知识」（3 个按钮 + 说明）。它属于「应用」阶段，读的时候不该占版面。

现在默认收成一行 `提炼成知识卡 · 约 N tokens`，点开才展开说明与三个按钮。**键盘可达**（`<summary>` 可聚焦），门禁里有一条断言钉住"默认收起但仍可见、可聚焦"。

## 二、怎么保证没删能力

| 保障 | 做法 |
| --- | --- |
| 入口仍可达 | 折叠用原生 `<details>`，DOM 里始终存在；浏览器冒烟里 `保存为知识卡` 仍能点到 |
| 文案不变 | 所有页面名保持原样，依赖文案的既有测试无需改写 |
| 结构有断言 | 品味门禁新增三条：四段分组、一级入口 ≤ 6、收藏/归档折叠为筛选 |
| 阅读区有断言 | 新增一条：提炼入口默认收起、仍可见、可键盘聚焦 |
| 全量回归 | 前端 339 项 + Rust 84 项 + **13 套**浏览器冒烟 + 旅程走查 13 项全绿（2026-10-22） |
| 折叠真的生效 | 2026-10-22 修：`.ws-nav-details { display: flex }` 覆盖了 `<details>` 收起的默认隐藏行为，「筛选」收起了里面的「收藏/已归档」却照样显示，还撑破了侧栏。补 `.ws-nav-details:not([open]) > *:not(summary) { display: none; }` |

## 三、没做的事（如实说明）

1. **没有重做视觉**。配色、字号、间距沿用既有 token，只动层级与暴露面。
2. **没有合并页面**。邮箱、订阅源仍是独立页——它们的配置形态差别太大，硬合并会让两边都变差。
3. **「原件库 / 向量库」没有单独做界面**。向量索引目前是检索的实现细节，用户不需要看见；如果以后要能手动重建索引，那才是它该露面的时机。
4. **没有做多来源的批量导入向导**。现在导入是"选文件 → 逐个解析"，来源一多确实会烦；这需要单独设计，不在本轮。
