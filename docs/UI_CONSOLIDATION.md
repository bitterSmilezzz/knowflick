# 界面收敛：从四段主线到三入口（第一套桌面 / apps/workbench）

> 问题：界面把「来源」「库」「应用」摊在同一层，同类入口重复出现，读一封信要面对一整块操作区。
> 做法：先按产品主线收敛为 **来源 → 收件箱 → 知识库 → 应用**（2026-10-22）；
> 产品重规划（ADR-0004，2026-10-24）把笔记升为一等资产后，再收敛为
> **笔记 / 知识库 / 应用** 三个一级目的地。
> 原则：**只改层级与暴露面，不删能力**。每个原有入口仍然可达——由
> `taste_usability_gate.mjs` 的路由对照断言自动检查（下表）。

## 一、改了什么

### 侧栏：三入口（2026-10-24，R1）

四段收敛之后，产品重规划把「可持续编辑的笔记」升为第一目的地（ADR-0004）。
采集手段（邮箱、订阅、导入）与处理状态（收件箱）不是与笔记并列的产品层，
并入「笔记」组：

```
笔记      全部笔记 · 收件箱 · 邮箱 · 订阅源 · （导入文件，动作）
知识库    全部知识
          ▸ 筛选    （收藏 / 已归档，折叠）
          ▸ 分类    （最多 8 个，折叠）
应用      ▸ 应用       （知识问答 / 认知简报 / 产物库 / 统计 / 知识测验，折叠）
          温故复习    （每天都要用，不折叠；按插件开关渲染）
```

**旧入口 → 新位置的路由对照**（UI_SPEC「旧入口迁移」要求可自动检查；
由 `taste_usability_gate.mjs` 逐条断言仍可达）：

| 旧入口（四段时代） | 新位置 |
| --- | --- |
| 全部笔记 / 收件箱 / 邮箱 / 订阅源 / 导入文件 | 笔记 |
| 全部知识 / 收藏 / 已归档 | 知识库 |
| 知识问答 / 认知简报 / 产物库 / 统计 / 知识测验 / 温故复习 | 应用 |
| 设置 | 底部（不变） |

页面切换时当前导航行自动滚进可视区——此前靠点击焦点的浏览器自动滚动兜着，
程序化导航（快捷键、深链接）兜不住，CI 的 Linux 字体行高下「知识测验」
曾被挤出 1040×640 视口（workspace_ui_smoke 红过）。

- **一级入口从 9 个收敛到 6 个**（邮箱、订阅源、收件箱、全部知识、知识问答、认知简报；
  复习按插件开关出现）。
  > 2026-10-22 追加：新增「统计」「知识测验」后一度涨到 9，超了 6 的约定。
  > 现在「应用」段整体收进一个可折叠区（`summary` 兼作组标签），**当前在应用页时
  > 自动展开**；「温故复习」留在折叠区外——它是每天都要用的高频入口。
  > 于是**一级入口实际为 4 个**（邮箱、订阅源、收件箱、全部知识）。
- **收藏 / 已归档** 折叠进「筛选」——它们是库的筛选条件，不是并列目的地。
- **分类** 折叠，带计数。
- **导入文件** 改成来源段内的动作按钮（`.ws-nav-action`），不再计为一个目的地：它是动词，不是位置。
- 折叠项带三角指示与计数，展开态截图已核。

### 顶栏：去掉与侧栏重复的入口

顶栏原有「语音转写 / 导入文件 / 导出备份」。导入与侧栏来源段完全重复，先删；
后来笔记软件本体把「手写 / 语音 / 转写」收进侧栏「记录方式」，顶栏的「语音转写」
与它成了**同一个动作**（`transcribeAudio`）的第二入口——插件关闭时甚至是两个
灰按钮各解释一遍「为什么不可用」。2026-10-24 一并删掉，顶栏只剩一个全局动作：

```
导出备份
```

### 空态：不再重复第三个「导入文件」

空库时原来侧栏、顶栏、空态三处都能导入。现在空态只给**用户还没看到的入口**：连接邮箱、添加订阅。

### 阅读区：整块操作区 → 一行入口

每条素材下面原本常驻一整块「从素材提炼知识」（3 个按钮 + 说明）。它属于「应用」阶段，读的时候不该占版面。

现在默认收成一行 `提炼成知识卡 · 约 N tokens`，点开才展开说明与三个按钮。**键盘可达**（`<summary>` 可聚焦），门禁里有一条断言钉住"默认收起但仍可见、可聚焦"。

## 二、怎么保证没删能力

| 保障 | 做法 |
| --- | --- |
| 入口仍可达 | 折叠用原生 `<details>`，DOM 里始终存在；浏览器冒烟里 `保存为知识卡` 仍能点到 |
| 文案不变 | 所有页面名保持原样，依赖文案的既有测试无需改写 |
| 结构有断言 | 品味门禁新增三条：四段分组、一级入口 ≤ 6、收藏/归档折叠为筛选 |
| 阅读区有断言 | 新增一条：提炼入口默认收起、仍可见、可键盘聚焦 |
| 全量回归 | 前端 552 项 + Rust 测试（通过、忽略分开报告，不以声明数代替通过数）+ **13 套**浏览器冒烟；以当前门禁执行日志为准 |
| 折叠真的生效 | 2026-10-22 修：`.ws-nav-details { display: flex }` 覆盖了 `<details>` 收起的默认隐藏行为，「筛选」收起了里面的「收藏/已归档」却照样显示，还撑破了侧栏。补 `.ws-nav-details:not([open]) > *:not(summary) { display: none; }` |

## 三、没做的事（如实说明）

1. **没有重做视觉**。配色、字号、间距沿用既有 token，只动层级与暴露面。
2. **没有合并页面**。邮箱、订阅源仍是独立页——它们的配置形态差别太大，硬合并会让两边都变差。
3. **「原件库 / 向量库」没有单独做界面**。向量索引目前是检索的实现细节，用户不需要看见；如果以后要能手动重建索引，那才是它该露面的时机。
4. **没有做多来源的批量导入向导**。现在导入是"选文件 → 逐个解析"，来源一多确实会烦；这需要单独设计，不在本轮。
5. ~~界面仍只在浏览器里验收（显示器长时间黑屏），真机窗口需要自己看一眼。~~
   2026-10-22 已解决：`tools/screenshot_real_app.sh` 会先唤醒显示器再按窗口坐标裁剪，
   `tools/real_app_pages.mjs` 用 cliclick 真实点击 + **内容区像素比对**确认页面真的切换了。
   真机逐页验证已能做。
