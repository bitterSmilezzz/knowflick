## 0. 接单和集成规则

1. 先读仓根 AGENTS、[MULTI_PLATFORM](../../MULTI_PLATFORM.md)、[产品路线](../../product/DELIVERY_ROADMAP.md)、本轮 REPORT/EVIDENCE。
2. **确认集成基线。** 本报告初始 HEAD 为 `65e1118` 加 5 个工作区文件；检查中这些文件被其他会话提交为 `9e8331c`，内容正是本轮审查的属性编辑版本。开工时再次 fetch，确认这些成果及本目录已在可获取的提交里。不要从旧 `origin/main` 开始另造一套工作台。
3. 一个短分支对应一个可验收增量，遵循仓库的 `workbench/...`、`chore/...` 等命名和显式暂存规则。分支在 GitHub 占位后再交给另一机器；不要复制工作树。
4. **同一 checkout 一次只允许一个 agent 修改同一业务链路。** 本文允许的并行默认指不同 checkout/工作树、明确分支所有者和合并顺序。测试中的反向验证会临时改写源码，也只能在自己的隔离 checkout 运行。
5. 保留旧卡片、素材、学习状态、跨端 JSON 契约和已注册入口；不恢复 Swift、不向冻结 JVM desktop 加功能、不主动引入 iOS。
6. 先建立能在基线失败的反例，再修改实现。不要通过删断言、放宽数量、延长全部等待、改文案掩盖故障。
7. 缺真实账号、设备或凭据时，继续完成合成/本地测试，明确保留“待真实验收”；不要自动使用私人数据、收费模型或发布产品。

### 建议批次

## T01 · 笔记保存会话统一与冲突保护

**解决：** KF-002、KF-004，以及同一保存链路的切换/关闭风险。优先级 P0。前置：可获取的当前集成基线。

**主要责任：** `NotesView.tsx`、新增笔记会话/保存协调模块、必要的 `repository.ts` 写接口；相关 UI/领域测试。若修改仓储接口，先告知 T02/T04 的执行者并给出稳定签名。

**实施要求：**

- 每篇笔记独立持有 noteId、已确认修订、当前草稿版本、dirty、inFlight、排队提交和冲突状态。
- 同一篇写入串行，合并保存中发生的新输入；旧提交完成不得把更新草稿标为已保存，也不得把 A 的修订/回执用于 B。
- 正文和元数据共用最新状态或补丁提交规则。收藏、笔记本、标签更新后，下一次正文保存不能回填旧值。
- 冲突时停止自动覆盖，保留本地副本与远端状态；不能只把 baseRevision 改成报错中的新数字。
- 新建另一篇、打开另一篇、路由离开、切库和关窗均先确定草稿处置。`beforeunload` 中 fire-and-forget 不是已持久化证明；桌面关闭要有可等待的保存/明确失败路径。意外退出用可恢复草稿降低损失。
- 失败保留内容、提供重试和清楚的状态；元数据编辑不应逐字符产生额外正文修订。

**必须验收：**

1. 设置笔记本/标签/收藏后续写，属性仍在。
2. 正文保存中连续输入、改属性，最后内容正确且没有假冲突。
3. 延迟 A 的保存回执，切 B 并编辑，B 不继承 A 的修订或 saved 状态。
4. 首次新建后尚未到 800ms 就点新建/切页，原草稿可找回。
5. 外部修订 2 与本地修订 1 冲突后继续输入，外部内容不被静默覆盖。
6. 写失败、重试、关闭与重开；最后一份被宣告“已保存”的内容必须在仓储中。

**交付：** 状态转换说明、失败先行的测试、浏览器与至少一条真实 Tauri 保存/关闭证据。没有桌面环境时只完成对应层，交由 T12 补验。

## T02 · 桌面笔记读取与回收站适配器契约

**解决：** KF-005。优先级 P1。前置：T01 的仓储写接口稳定。

**主要责任：** `repository.ts` 读取部分、`shell/store.ts`、`notes.rs` 与 Tauri 笔记命令；权限/注册清单仅在签名或命令改变时同步。

**实施要求：** 明确定义 active、deleted、all 的语义和分页。当前 Rust 的 `include_deleted=true` 仅返回 deleted；决定是否保留这一实现或引入显式 scope，不能在不同调用方各自猜。UI 列表、回收站和备份应使用各自正确的查询范围。

**必须验收：**

- 浏览器与桌面跑相同契约样本；不是只分别测试 SQL 和纯函数。
- 超过一页、不足一页、空页、查询失败均确定处理；不把 10000 写成新的永久上限。

**交付：** 一份共享测试向量和两种适配器结果；更新相关契约说明。T03/T04 可依赖该查询接口。

## T03 · 独立的完整备份采集与导出

**解决：** KF-001、KF-008。优先级 P0。前置：T01、T02；与 T06 的包格式接口确定后可并行实现。

**主要责任：** `Workspace.tsx` 两个导出入口、备份采集服务、仓储分页读取、媒体读取；不接管 T04/T05 的恢复写入。

**实施要求：**

- 从权威仓储获取数据，界面是否挂载/用户是否点过笔记页不影响备份。
- 给当前草稿一个明确保存或保留结果；不能在导出回执中提前声称已包含尚未持久化内容。

- 附件/产物读失败有结构化清单；“完整”和“部分”必须有不同回执。保留原始引用，不用无声跳过伪装完整。
- 包内计数与实际条目一致；必要时分批/流式处理，先测量再优化，避免不必要地复制多份媒体到内存。

**必须验收：** 冷启动直接导出；不打开笔记页；未保存输入；外部变更；回收站；两处入口；10001 笔记/素材与 1001 产物；缺附件、无权限、仅正文引用附件；新目录恢复后重启并逐字段/字节核对。

**交付：** 一个备份采集入口、明确完整性结果、真实下载包样本清单。合成大规模包不入 Git。

## T04 · 笔记恢复专用契约与知识库映射

**解决：** KF-003、KF-006 的落库语义。优先级 P0。前置：T02、T07、T06 的预检结果接口。

**主要责任：** `notesRestore.ts`、`repository.ts` 恢复接口、`notes.rs`、必要 schema/迁移与命令接线。与 T03/T05 约定输入和结果，不在 Workspace 中重复定义规则。

**实施要求：**

- 区分空库恢复和向已有库合并。空库保留包内修订、created/updated/deleted/archived、来源和属性。
- 合并冲突策略写进 NOTES_MODEL：本地修订不可无声回退；显式覆盖与普通编辑分开，说明恢复后的下一修订号。
- 不要求伪造包内没有的全部修订历史；需要历史基线/恢复记录时明确其含义，继续满足不复用修订号的约束。
- 同名异 id、同 id 异名分别处理；合并成员时用 id 映射，保留或明确转换 addedAt。不能捕获错误后继续假计数。
- 校验 sourceMaterialId 与成员引用，重复恢复应幂等或有可解释变化。
- 回收站记录仍然保持删除态；不能通过普通 upsert 自动复活。

**必须验收：** revision=9 的正常和删除笔记恢复；时间戳；元数据；同名库；多库关系；冲突已有笔记；不存在来源；重复恢复；恢复后编辑产生正确下一修订；既有卡 id/FSRS 不变。两种仓储都验证。

**交付：** 恢复契约更新、专用操作、逐字段数据库断言。包解码测试不得替代数据库断言。

**解决：** KF-009。优先级 P1，可先开展。主要责任：`systemBackup.ts`、ZIP 读写边界、格式文档与测试；与 T04/T05 约定“校验通过的恢复输入”。

## 共同交付格式与验证命令

每个任务交付一段可独立阅读的记录：

```text
任务：Txx；解决问题：KF-xxx
基线与最终提交：...
变更行为：用户在什么条件下，原来发生什么，现在发生什么
关键取舍与兼容：...
回归：哪个用例在基线失败，修复后通过
验证：命令、平台、PASS / FAIL / SKIP / 缓存、证据文件
未验证条件：...
后续依赖：...
```

按修改范围至少执行仓库约定的验证，不以新增小测试代替整个相关门禁：

```sh
./tools/verify_workbench.sh
cd apps/workbench && npm run build
```

浏览器门禁必须启动自己拥有的服务；支持 `KNOWFLICK_UI_URL` 的本地套件可使用独立端口。测试服务要与被验证提交一致，不能用遗留安装包或另一个 checkout 代表当前源码。反向验证临时改写源码时避免与浏览器 HMR/其他 agent 混跑。

涉及 Kotlin 共享模块：

```sh
cd apps/android
./gradlew :domain:jvmTest :shared-data:jvmTest :shared-ui:jvmTest :desktop:test
```

涉及 Android 宿主：`./tools/build_android.sh`；实际设备交互另验。涉及共享契约：

```sh
python3 tools/check_taxonomy.py
python3 tools/check_clip_parity.py
```

Python 按 AGENTS 优先本机 Python 3.15，目标项目明确钉版本时除外。所有临时包、录屏、日志写 `.scratch/<任务>/`，正式结论写 `docs/`；不提交媒体模型、构建产物、私人备份或凭据。
