# KnowFlick 实际问题审查与执行文档

日期：2026-10-25（Asia/Shanghai）。用途：项目所有者确定修复顺序，并将具体任务交给其他 agent。

**结论：当前最需要收口的是笔记保存、备份和恢复的可信度。现有学习能力、跨端契约和自动化基础应当保留；新笔记功能还不能按“数据闭环已验收”交付。** 本轮实际复现了漏备份、冲突后覆盖、恢复状态变化等问题。通过编译、单元测试和已有浏览器冒烟，均不足以排除这些问题。

按以下顺序阅读：

1. [审查报告](REPORT.md)：基线、架构、16 项问题、产品缺口、优先级与发布判断。
2. [执行任务书](TASKS.md)：14 个可分派工作包，含依赖、修改边界、验收用例和交付要求。
3. [验证与复现记录](EVIDENCE.md)：实际执行结果、原始观测摘要、复现方法与未验证范围。

第一阶段优先完成 **T01 笔记保存**、**T02 桌面回收站**、**T03 完整备份采集**、**T04 恢复契约**，按任务书依赖顺序派发。T01 必须由一个 agent 统一负责正文、属性、切换和冲突，避免多人分别修补同一状态机。其他任务能否并行，以 TASKS 的文件所有权和前置依赖为准。

本目录描述检查时的工作区，**不是修复完成记录**。每个执行 agent 在自己的交付记录中登记解决了哪些 KF 编号；不能直接把本报告里的“已复现”改成“已修复”，也不能以本报告代替修改后的验证。

本轮只交付审查材料，没有修改产品实现，也没有合并或发布。开始检查时已有的 5 个未提交文件没有被本轮改写；检查中另一会话将它们提交为 `9e8331c`，本轮复现覆盖的正是这些内容。另一台机器使用本目录前，需要通过 GitHub 获取包含审查文档的提交；本机工作区文件不会自动同步到其他机器。
