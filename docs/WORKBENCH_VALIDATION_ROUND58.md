# Round 58 验证记录

## 跨端回环判定统一

三端各写一套字符串比较，对同一地址的判定会不同：

| 位置 | 原写法 | `0:0:0:0:0:0:0:1` |
| --- | --- | --- |
| 桌面壳 `http.rs` | `Ipv6Addr::is_loopback` | ✅ 回环 |
| 桌面前端 `ingest.ts` | 字符串比 `"[::1]"` | ❌ 不是回环 |
| 安卓两处 | 字符串比 `"::1"` | ❌ 不是回环 |

同一份 `settings.json` 写着 `http://[::1]:11434/v1` 时，桌面端认它是本机（免密钥、
允许 HTTP），安卓端不认（要密钥）——违反 ADR-0002 §3「同一份文件在两端行为相同」。

统一后三处口径一致：127.0.0.1 / localhost / IPv6 回环。`::ffff:127.0.0.1` 这类
IPv4 映射写法**不算**回环（Rust 端 `Ipv6Addr::is_loopback` 同样不认，两端才对齐）。

| 证据 | 结果 |
| --- | --- |
| 桌面前端 `loopback.test.ts` | 9 项通过 |
| 安卓 `LoopbackHostTest.kt` | 8 项通过，0 失败 0 跳过 |
| `tools/check_loopback_parity.mjs` | 16 个地址逐条一致 |

**反向验证**：把 TS 判定改窄，跨端对照立刻报出
`"127.0.0.1"：Rust=true TypeScript=false`。

## 对照脚本本身踩的三个坑

| 坑 | 症状 | 修法 |
| --- | --- | --- |
| `spawn npx` 在 Windows 上 ENOENT | Windows 的 release 门禁红 | 用 node 直跑 `node_modules/vitest/vitest.mjs` |
| 解析要求行首是 `PARITY` | **三端一起红**（CI 上 vitest 加前缀并缩进） | 改行内匹配 |

按行首匹配时**本地 16 条全中、CI 一条都不中**。已用「CI 风格输出」复现验证。

第三个坑是代价问题：门禁里的检查**贵到超时等于没有**——它不报问题，只让流水线卡住。

## Linux job 连续两次超时

查 step 时间戳发现两次都卡在第 3 步「安装 Linux 系统依赖」（apt 源不响应），
verify 那一步根本没开始——不是门禁太重。修法：超时上限 25 → 45 分钟（release 45 → 60），
apt 加 `Acquire::http::Timeout=30` 与重试。
