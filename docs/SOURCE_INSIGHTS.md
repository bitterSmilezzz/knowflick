# 越用越懂你：来源价值模型（第一套桌面 / apps/workbench）

> 目标：邮件只是来源之一。知识库应该从**你已经做过的事**里学出偏好，
> 把更可能被你留下的内容排在前面，并且**说得出为什么**。
> 实现位置：`src/domain/insights.ts`（模型）+ `src/ui/workspace/SourceInsightPanel.tsx`（面板）。

## 一、它学什么

模型只统计**用户明确做过的动作**，不做任何推测（不看点击、不看停留时长、不看打开次数）：

| 动作 | 权重 | 为什么 |
| --- | --- | --- |
| 转成知识卡 | 5 | 你把它拆成了可复习的原子单元，这是最高强度的留存 |
| 收藏 | 3 | 明确表达「留着」 |
| 复习过（`reviewCount > 0`） | 记录，不加权 | 一张卡被复习，说明它已经是卡了；额外加权会让「研究很久但没留住」的来源压过新鲜内容 |
| 归档忽略 | −0.6 | 明确表达「这个来源不太值」 |

- **窗口 90 天**：更旧的内容完全不参与统计，避免一年前的偏好压住现在的习惯。
- **近期加权**：窗口内的内容按时间衰减（1 周内 1.0，窗口边缘 0.2）。
- **同类归一化**：账号级聚合了所有邮件，直接和单个发件人比分数会不公平，所以分数按「同类内最高分」归一化。

## 二、它长什么样

设置页里有一块「你的来源贡献」，列出分数最高的 6 个来源，每个带一句**可核对的说明**：

```
c@x.test   1 条内容：1 条已沉淀为知识卡，1 张卡已收藏，1 张卡已复习   100%
b@x.test   1 条内容，还没有收藏、沉淀或复习                          50%
```

说明是从计数直接生成的——你看到的每个数字都能在自己库里找到出处。

## 三、它怎么用在邮箱上

邮箱列表默认「最新在前」。开启个性化后：

- **邮件**按发件人权重分层，同一权重层内仍按时间倒序——新邮件永远不被埋掉；
- **主题组**按组内最高权重排序，因为组是显示单元，一个组里有值得回看的内容，整个组就该提前。

关闭个性化后排序退回「最新在前」，并且面板会明说：「个性化已关闭：邮箱与来源列表按时间排列，不做偏好排序。」

## 四、边界（如实说明）

1. **没有隐式学习**。开关只存在 `settings.json` 的 `personalizationEnabled`，默认开启，可在设置页关闭；关闭时前端不计算洞察，也不做任何排序改动。
2. **不改数据库**。洞察是**每次从素材与卡片派生**的，没有单独的偏好表。所以「重置」等于把卡片和归档清空，不会残留旧偏好。
3. **来源识别依赖元数据**：邮箱按账号 + 发件人地址，订阅按 `subscriptionId`，网页剪藏按域名。手工记录、导入文档没有可识别的来源标识，归为「闪念 / 导入文档」。
4. **超过 90 天的旧来源完全不计**：这是有意的，不是遗漏。想让某个来源重新获得权重，把它最近的内容转成卡或收藏即可。
5. **这一轮没有把偏好用于 AI 提示词或知识问答**，只用于排序与展示。让 AI 使用偏好需要显式设计与提示注入，风险更高，留到后续。
6. **没有接真实用户数据验收**：全部结论来自隔离会话里的种子数据与自动化断言。

## 五、验证

| 层 | 命令 | 结果 |
| --- | --- | --- |
| 模型（排序 / 权重 / 窗口 / 归一化） | `npx vitest run src/domain/insights.test.ts` | 8 项通过 |
| 面板（有信号 / 无信号 / 关闭态） | `npx vitest run src/ui/workspace/SourceInsightPanel.test.tsx` | 3 项通过 |
| 界面端到端（排序改变 / 开关落盘） | `node tools/mailbox_ui_smoke.mjs` | 45 项检查通过 |
| 全量门禁 | `./tools/verify_workbench.sh` | 前端全绿 |

端到端里专门钉了两条排序断言：**开启个性化时最旧但已沉淀的邮件会提前**，**关闭后立刻退回「最新在前」**。这两条在实现过程中各暴露过一次真实缺陷（主题分组覆盖了邮件级排序；主题组之间的顺序没有跟随权重），都已修复。
