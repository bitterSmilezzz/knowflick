# ADR-0002：桌面三端与网页一套，安卓单独一套

- 状态：**已接受**（2026-10-13）
- 决策人：项目所有者
- 替代： [ADR-0001](0001-desktop-tri-platform-shared-kotlin.md) 里「桌面三端与 Android 共用一份界面」这条**活计划**。0001 的实测记录仍然有效，已经落地的 Kotlin 共享代码不因本决定删除。
- 相关： [AGENTS.md](../../AGENTS.md) · [CLIP_INGEST_DESIGN_2026-10.md](../CLIP_INGEST_DESIGN_2026-10.md)

## 1. 决定

按交互形态分，不按操作系统拆成六份。

| 套 | 端 | 技术 | 现在 |
| --- | --- | --- | --- |
| 第一套 | Windows、Linux、macOS，以及稍后的网页 | 一份 Web 界面（Vite + React + TypeScript）+ Tauri 壳。Rust 只做窗口、本机文件、系统菜单。卡片规则写在 Web 这层 | **要做的桌面**。第一版只交三个桌面程序 |
| 第二套 | Android | 现有 Kotlin / Compose（`:app` + `:domain` + `:shared-data` + `:shared-ui`） | 保持现状，不挡第一套发布 |
| 第三套 | iOS | 未定 | **先不做**。真要做时可以单独成套，不与安卓绑成一个框架 |

Windows 不单独成套。两个手机不合成一套。六端也不再追求一份界面。

已落地的 JVM + Skiko 桌面（`:desktop`）**冻住**：不再加功能。第一套能把下面的闭环跑通之前，不删 `:desktop`。

## 2. 第一版做什么

交付物是装在 Windows、Linux、macOS 上的程序。浏览器里直接打开的网站，等这个闭环能用再开，用同一份界面。

第一版包括：剪藏、笔记导入、AI 出卡、刷卡、卡库和详情、收藏和历史、测验、统计、导出。卡片能划走，并显示分类、标题、摘要。

不作为第一版完成标准：摄影底图、Cutline 视觉。

不进第一版：知识图谱、局域网同步、环境音、朗读、海报、桌面微件、学习地图、卡片聊天，以及条目（Entry）、wiki、暂存队列、问答式卡面、`kf_ingest`。这些条目模型继续不要写进 [CONTEXT.md](../../CONTEXT.md)。

剪藏的抓取走壳。页面里直接请求外站会被浏览器同源策略拦住。

## 3. 两套之间共享什么

共享文件，不共享界面代码。

- 一个数据目录，默认放在用户主目录下。
- `cards.json`、`cards.backup.json`、`settings.json` 按安卓现在的结构读写。拷过去就能打开，中间不经转换。
- 刷卡、收藏、SM-2 / FSRS 字段按现在的 Kotlin 规则解释。同一份文件在安卓上打开，到期和喜好不变。第一版不改算法。
- API 密钥单独一个文件，由壳读写。不进卡片 JSON，不进设置 JSON，不进备份包。
- AI 沿用现状：用户自己填 OpenAI 兼容接口和密钥。不做 KnowFlick 账号，不代管模型。

## 4. 后果

- 桌面新功能写在 `apps/workbench`，不写进 `:shared-ui` 或 `:desktop`。
- 安卓继续用现有模块。第一套不要求安卓同时改出同样的界面。
- 0001 之后「一套 Kotlin 界面覆盖桌面和安卓」不再是活计划。安卓内部仍然是一份 Kotlin 代码；第一套内部仍然是一份 Web 代码覆盖三个桌面。
- 本决定只改文档，不改代码，不删 `:desktop`。
