# 第二阶段第十二刀：IMAP 会话协议层迁到 Go（mail 第三批）

> 承接 ADR-0019/0020。前两批做了配置、凭据、账号表；这一批做**协议层**：连接、命令、登录、只读打开文件夹。
> 邮件正文抽取与同步执行仍未迁。

## 一、迁了什么

| 能力 | Go | 与 Rust 的关系 |
| --- | --- | --- |
| 只读命令白名单 | EnsureReadOnly | 拒绝 STORE/DELETE/EXPUNGE/COPY/APPEND/MOVE/CREATE/RENAME/SUBSCRIBE/UNSUBSCRIBE |
| 字符串引号 | Quote | 转义反斜杠与双引号 |
| 文件夹编码 | MailboxName | IMAP modified UTF-7（RFC 3501 5.1.3），含代理对 |
| 会话 | New | 校验问候是 `* OK` |
| 命令 | Command | 标记完成、未标记行、字面量；服务端原文**不回传** |
| 登录并只读打开 | LoginAndExamine | LOGIN + EXAMINE，返回 UIDVALIDITY 与邮件数 |

三层上限原样保留：单行 8 MiB、单次响应 16 MiB、行数 100000；单封 2 MiB。
会话预算 120 秒、socket 超时 15 秒。

## 二、四条安全约束

1. **只读命令白名单是硬闸**：`Command` 入口先过 `EnsureReadOnly`，写命令连发都发不出去。
2. **服务端原文不回传**：认证失败的响应原文可能带着刚提交的密码。错误信息只说「请检查账号密码与文件夹名」。
3. **TLS 始终校验**：生产代码没有明文开关（Rust 的明文路径在 `#[cfg(test)]` 里，Go 侧本轮只做了协议层，传输由调用方提供）。
4. **三层上限**：单行/单次响应/行数都设硬上限，异常响应不会把内存吃满。

## 三、测试里踩到的四个坑（都值得记）

### 3.1 UIDVALIDITY 在方括号里

`* OK [UIDVALIDITY 42] done` 的最后一个「数字」是 `42]`，只裁圆括号会解析失败。
修法：`strings.Trim(field, "()[]")`。

### 3.2 中文编码的期望值不能靠猜

我先写了一个「应该是 &6Ik-」的常量，实测是 `&g0l6Pw-`——我算错了。
改成断言**结构**（以 `&` 开头、`-` 结尾、原文不再出现）加跨运行时对拍，而不是猜一个 base64 变体值。

### 3.3 `net.Pipe` 是无缓冲同步管道

用它测「超时」会死锁：服务器不读，客户端连命令都发不出去。修法是让服务器侧持续读并丢弃。

### 3.4 同一个过期时钟算不出过期

如果 `New` 和 `Command` 用同一个固定时刻，`deadline = 该时刻 + 120s` 仍在过去，判据永远不触发。
必须用**可推进**的时钟。第一版就这样写错了，测试挂死 30 秒才暴露。

## 四、验证

| 用例 | 内容 |
| --- | --- |
| Go 9 项 | 11 条写命令全被拒、4 条读命令放行；引号转义；中文/ASCII/&/混合文件夹编码；非 OK 问候被拒；LOGIN+EXAMINE 解析 UIDVALIDITY 与 EXISTS；失败响应不泄露密码；超大 literal 被拒；过期会话立刻报错；缺 UIDVALIDITY 报错 |
| 跨运行时对拍 | Rust `go_imap_protocol_parity` 比对同一组输入的引号转义与四种文件夹编码，**逐字一致** |

## 五、还没做

| 项 | 现状 |
| --- | --- |
| **TCP + TLS 连接** | 没迁。Rust 用 native-tls（TLS 1.2 起、系统根、主机名校验、DNS 超时、8 个地址逐个尝试）；Go 侧本轮只做协议层，Transport 由调用方提供 |
| UID SEARCH / UID FETCH | 协议层已有 Command，但没封装成具体方法 |
| 邮件正文解析与落素材 | 未迁 |
| 同步执行、进度与去重写入 | 未迁 |
| 真实 IMAP 账号 | 一直未验 |

**Go 版现在能构造只读 IMAP 会话并登录打开文件夹，但还不能真正连服务器**（TLS 连接未迁）、**不能同步邮件**。
