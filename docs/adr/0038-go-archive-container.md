# 第二阶段第二十九刀：归档容器（.kfbackup / 卡片 ZIP）读写迁到 Go

> 承接 ADR-0036（e2ee）与 ADR-0037（命名）。命名与加密都有了，这一刀补上
> **容器本身**：ZIP 里装什么、怎么读、导出前剥什么。

## 一、迁了什么

| 能力 | Go | 与 Rust 的关系 |
| --- | --- | --- |
| 魔数与上限 | IsZIP / MaxArchiveBytes | PK 魔数；50 MiB 上限，超了直接报错 |
| 读归档 | Read | ZIP 走容器解析；否则当纯文本卡片正文 |
| 打包 | Write | 标准库 archive/zip，存储方式（不压缩） |
| 密钥剥离 | StripSecretSettings | 导出前剥掉密钥字段 |

### 1.1 读的口径

- ZIP 内按**小写**文件名匹配 `cards.json` / `settings.json`，允许一层目录前缀；
- `cards.json` 缺失报「ZIP 中未找到」，为空报「未检测到有效的卡片数据」；
- 非 UTF-8 条目报「<名字> 不是 UTF-8」；
- 非 ZIP 输入当作纯文本，空白则报「未检测到有效的卡片数据」。

**空 cards.json 必须拒绝**：否则一次误操作会把空卡库当成正常导入。

### 1.2 密钥剥离是硬承诺

导出包是**用户会分享的文件**，界面写着「不含 API 密钥」。`settings.json` 里若留着密钥
（用户手改过、或旧版本写过），原样打包就把它带出去了。

键名小写后含 `apikey / api_key / token / secret / password / passwd / credential / auth` 任一即剔除；
坏 JSON 原样返回（导出不该因为设置文件坏了就失败）。

## 二、一条被钉住的过度匹配

`author` 和 `authored` 都含 `auth` 子串，**按规则都会被剔除**。

我第一版测试期望 `author` 保留，结果被实现纠正。这不是实现的错——是 Rust 的
`lower.contains(needle)` 就是子串匹配，**「作者」字段会被当成认证字段丢掉**。

迁移的职责是保真而不是顺手修好：这里照抄，并把这条行为写进测试钉住。
如果哪天改成整词匹配，这条测试会失败，提醒我们那是一次**行为变更**而不是重构。

## 三、验证：双向读

容器格式不是我们的契约，**能被对方读开才是**。所以两边都写、两边都读：

| 方向 | 结果 |
| --- | --- |
| Go 打包 → Rust 读（`go_archive_reads_in_rust`） | 通过：卡片正文、theme 保留、`apiKey` 与密钥值都不在 |
| Rust 手写 `zip_store` → Go 读（`rust_archive_writes_for_go` 写 + `TestReadRustArchiveFixture` 读） | 通过：卡片逐字一致，密钥未泄漏 |

Go 侧另有 6 项单测：纯文本读、非 UTF-8 拒绝、50 MiB 上限与 PK 魔数、
写读往返（含密钥已剥）、嵌套路径与大小写、空 cards.json 拒绝、密钥剥离规则。
