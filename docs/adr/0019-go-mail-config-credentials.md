# 第二阶段第十刀：邮箱配置与凭据（mail 第一批）迁到 Go

> mail.rs 有 2265 行，是剩余最大的模块。这一刀只迁安全边界：配置校验与凭据存储。
> IMAP 会话、同步游标与导入流水留给后续批次——先把最容易出事的部分对齐。

## 一、迁了什么

| 能力 | Go | 与 Rust 的关系 |
| --- | --- | --- |
| 账号 id 校验 | ValidID | 标准 UUID；不合法直接拒 |
| 配置校验 | Validate | 五个必填字段的长度与控制字符、邮箱形状、端口、同步封数 1–200、间隔 0 或 5–1440、主机名形状（不能带协议前缀或端口） |
| 凭据路径 | CredentialPath | credentials/mail-uuid；目录或文件是符号链接即拒 |
| 凭据读 | ReadPassword | 权限太宽（组/其他人可读）就报错，不顺手修好 |
| 凭据写 | WritePassword | 临时文件 0600 到 Sync 再到 Rename；目录置 0700；失败清临时文件 |
| 凭据删 | RemovePassword | 不存在不算错（删账号要幂等） |

## 二、两处刻意不做贴心

### 2.1 不给 syncLimit 兜默认值

我第一版写 if SyncLimit == 0 就设成 50，理由是省得用户填。
测试立刻抓到：Rust 会拒绝 0，而 Go 会静默改成 50——同一个界面操作在两侧得到不同结果。

去掉默认值，与 Rust 保持一致：0 是错误输入，不是用默认。

### 2.2 读凭据不修权限

Rust 在权限过宽时报错而不是 chmod。这不是偷懒：静默修权限会掩盖这个文件曾经被别人读过的可能。
Go 侧照抄这个判断。

## 三、验证

| 用例 | 内容 |
| --- | --- |
| Go 6 项 | 合法配置去空白与默认文件夹；10 条拒绝规则逐条命中；凭据往返 + 文件 0600 / 目录 0700 + 无临时文件残留；权限放宽后读被拒；符号链接目录被拒；密码长度与控制字符 |
| 跨运行时对拍 | Rust go_mail_config_parity 用同一批 10 条配置（含间隔 0 关闭同步这条放行），与 Go Validate 结论逐条一致 |

## 四、还没做

| 项 | 现状 |
| --- | --- |
| IMAP 会话 | 完全没迁。Rust 的只读约束（只发 LOGIN/EXAMINE/UID SEARCH/UID FETCH BODY.PEEK[]）、TLS 始终校验、15 s socket 超时与 120 s 会话预算都还在 Rust 侧 |
| 账号表与同步游标 | 未迁（mail_accounts、mail_imports 去重账本） |
| 邮件正文抽取与落素材 | 未迁（2 MiB/封、512 KiB 文本上限） |
| 备份包里的邮箱数据 | 未迁 |
| 真实 IMAP 账号 | 一直未验（缺凭据） |

明确说清楚：Go 版现在能校验配置、能安全存密码，但不能连邮箱、不能同步。
说邮箱迁完了是不诚实的。
