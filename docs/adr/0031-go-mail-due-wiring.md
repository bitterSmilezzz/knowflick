# 第二阶段第二十二刀：把调度循环接到真实同步

> 承接 ADR-0030。RunDue 只调 Syncer 接口；这一批把 Syncer 实现接到 mailrunner。

## 一、迁了什么

| 能力 | Go | 与 Rust 的关系 |
| --- | --- | --- |
| 一轮到期同步 | SyncDue | 对应 sync_due_accounts：查库、查账号、查密码、串行跑 |
| 适配器 | dueSyncer | 把账号 id 变成一次 mailrunner.Run，返回 (imported, rejected, err) |
| 尝试时间 | dueSyncer.Sync 开头 | 与 Rust 的 sync_attempt 同序：先写 last_attempt_at，再读密码、再连接 |
| 并发保护 | SyncDue 持 mailschedule.Lock 整轮 | 自动同步与「立即同步」不会同时推进同一行游标 |

## 二、为什么先记尝试时间

dueSyncer.Sync 第一件事是写 last_attempt_at，而不是等到连上服务器之后。

原因：密码缺失、TLS 握手失败也是一次「尝试」。如果用成功时间或只在连上之后记，
失败账号每次轮询都会立刻重试——不断撞服务器，还可能触发对方风控。

这一条与 ADR-0029 的「用尝试时间而不是成功时间」是同一个决定，只是落到了更精确的位置。

## 三、验证

| 用例 | 内容 |
| --- | --- |
| 端到端 | 两个到期账号：一个有密码且连本地假 IMAP 服务器 → 导入 2 封、无错误；另一个没密码 → 报错但不阻断前一个。库里最终 2 个素材 |
| 间隔生效 | 同一时刻再跑一轮 → 一个账号都不再连 |
| 跨运行时对拍 | Rust go_mail_due_parity 用 Go 导出的真实结果断言：成功账号 imported=2、hasError=false；缺密码账号 hasError=true |

对拍刻意断言的是**真实导出的结果**，不是「我猜应该是 2 封」——和 ADR-0025 里猜素材 id 的教训同源。

## 四、还没做

| 项 | 现状 |
| --- | --- |
| 定时器 | 未做。SyncDue 是「跑一轮」，没人按分钟调用它 |
| 界面入口 | 未做。Go 预览界面没有邮箱入口 |
| 真实邮箱 | **未验**。端到端只对着本地假服务器跑过 |
| 备份包里的邮箱数据 | 未迁 |

**Go 版现在能把「到点同步」完整跑一轮**，但只在假服务器上验证过，且没有定时器与界面入口。
