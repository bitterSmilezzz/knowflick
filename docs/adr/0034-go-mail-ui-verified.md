## 二、抓到的真 bug：手动同步被到期判定吞掉

**第一次点「立即同步」的结果是「邮箱同步：导入 0 封，拒收 0 封」**——看起来一切正常，
实际上什么都没做。

根因：SyncMailDueNow 走的是「到期判定」，而测试账号的 syncIntervalMinutes 是 0
（关闭自动同步）。于是它不被判定为到期，被静默跳过，**连错误都没有**。

这与 Rust 的语义不同：Rust 的 sync_account(dir, id) 是**手动同步这个账号**，
不受 sync_interval_minutes 影响。间隔为 0 表示「不要自动跑」，不是「不许手动跑」。

修法：

- mailrunner.NewAccountSyncer 暴露「直接同步这个账号」的能力，不经过期判定；
- MailService.SyncMailAccountNow(accountID) 用它，逐个账号跑；
- 界面「立即同步」改成逐个调用，不再走 SyncMailDueNow。

修完再点一次，结果变成「邮箱同步：导入 0 封，拒收 0 封，1 个账号报错」，
并显示具体原因「还没有保存这个账号的密码」。**这才是「真的尝试过」。**

## 三、回归测试

TestSyncMailAccountNowIgnoresInterval：账号 syncIntervalMinutes: 0，同步到一个
关闭端口（127.0.0.1:1，确定性失败）。断言 outcome.AccountID 正确且 outcome.Error 非空——
即「尝试了并报了错」，而不是「被间隔判定静默跳过」。用关闭端口而不是外网域名，避免测试依赖网络。
