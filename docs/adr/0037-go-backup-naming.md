# 第二阶段第二十八刀：备份命名与日期换算迁到 Go

> `.kfbackup` 的容器格式还没迁，这一刀先迁它的「**写到哪个文件名**」——
> 备份文件名选错的后果是覆盖已有备份，等于备份不存在。

## 一、迁了什么

| 能力 | Go | 与 Rust 的关系 |
| --- | --- | --- |
| 民用日期换算 | CivilFromDays | Howard Hinnant 的 days_to_civil，与 Rust 的 civil_from_days 逐字一致 |
| 文件名日期 | DateFromMillis | 先除 1000 再除 86400（整数除法向零截断），**不做时区换算** |
| 下一个可用名 | NextLocalName | 从 `-01` 起找第一个空位，同一天最多 99 次 |
| 超限报错 | ErrTooManyBackups | 找不到就报错，**绝不覆盖** |

## 二、两条刻意的简化

### 2.1 不做时区换算

文件名只需要「哪一天」。用本地时区会让同一个 UTC 午夜在两台机器上得到不同日期，
而备份文件名是跨设备比对用的。**这是刻意的口径，不是遗漏**——与 Rust 一致。

### 2.2 找第一个空位，而不是最后一个之后

Rust 的循环从 `seq=1` 起，撞到不存在的名字就停。
所以已有 `-01` 和 `-03` 时选 `-02`，不是 `-04`。

我第一版测试写成了「跳到 `-04`」——那是我把「跳过空位」理解成了「排在最后之后」。
实现没错，是断言错了。这一条单独记下来：**看着很像的两种语义，测试会替你分清**。

## 三、验证

| 用例 | 内容 |
| --- | --- |
| Go 5 项 | 日期换算（epoch、负数、跨年、闰年）；毫秒换算与跨午夜边界；命名找空位（含跳过别的日期、跨年日期）；99 次上限报错且提示用户「清理目标目录」；排序稳定 |
| 跨运行时日期对拍 | Rust `go_civil_from_days_parity` 逐条核对 **12 个天数**，含 `-1000000`（→ -768-02-04）、`-1`、`0`、`19000`、`730122`（→ 3969-01-03）、`100000000`（→ 275760-09-13） |
| 跨运行时命名对拍 | Rust `go_backup_name_parity` 用同一条规则复算 **5 组**（空目录、只占 `-01`、占 `-01` 与 `-03`、别的日期干扰、跨年日期），与 Go 选出的名字逐字一致 |

负数与超大天数都被覆盖：这两个区间最容易在整数除法的「向零截断 vs 向下取整」上出分歧，
而一旦出分歧，1970 年前的日期与远期日期都会写错。

## 四、还没做

| 项 | 现状 |
| --- | --- |
| `.kfbackup` 容器格式 | **未迁**。打包与解包都还在 Rust |
| WebDAV 上传的命名退让 | 未迁。注意它与本地命名**规则不同**：WebDAV 先试纯日期名，冲突才退到 `-01` |
| e2ee 接入容器 | 未做（e2ee 已迁，见 ADR-0036） |
| 真实备份/恢复往返 | 未验 |

**Go 版现在知道该写哪个文件名，但还不会打包。**
