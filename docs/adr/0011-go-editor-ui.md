# 第二阶段第二刀：界面接上编辑与回收站

> 承接 [ADR-0010](0010-go-write-path-parity.md)。那一轮把写入语义对拍钉死；这一轮把它们接到真实界面。

## 一、做了什么

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 启用编辑 | 窗口右上「启用编辑」 | 默认只读；点了才以 `mode=rw` 重开同一个文件 |
| 保存 | 标题/正文编辑框 + 「保存」 | 走 `SaveNote` → `Upsert`，修订与 FTS 同步由 Go 数据层负责 |
| 移进回收站 | 「移进回收站」 | 走 `DeleteNote` → `Delete`，索引立即移除 |
| 冲突提示 | 保存失败 | 明确说「这篇笔记已被别处改动（当前修订 N）」，并刷新列表；**不静默覆盖** |

**默认只读这条没有放松**：重新选择资料库一律回到只读（`ChooseLibrary` 内部固定 `writable=false`），避免「顺手」继承写权限。

## 二、原生窗口实测（副本，不碰真实库）

用阶段 1 写入夹具的副本 `.scratch/go-migration/phase2/edit-qa.sqlite`，启动 Go 预览，全程走**真实 WebView 的无障碍树**：

| 步骤 | 界面证据 | 数据库证据 |
| --- | --- | --- |
| 初始只读 | 标题栏显「（只读）」；有「启用编辑」按钮；正文渲染出标题与三段 Markdown | `…` |
| 点「启用编辑」 | 回执「已启用编辑：保存会写进这个资料库文件」；出现标题输入框、正文 textarea、「保存」「移进回收站」；无改动时「保存」禁用 | — |
| 改标题并保存 | 回执「已保存（修订 3）」；列表同步变成新标题；出现「修订 3」 | `current_revision` 2→3，标题为改后值，`note_revisions` 2→3 条 |
| 移进回收站 | 回执「已移进回收站」；列表变「已显示 0 篇」与「这个资料库还没有笔记」 | `is_deleted=1`，`fts_notes` 对应行数 0 |

### 一个过程中的 bug（已修）

首版回执显示「已保存（修订 undefined）」——`SaveOutcome` 的 Go 字段加了 `json` 小写标签，但界面里还写着 `outcome.Revision`。
修法：同步改成 `outcome.revision` 并重跑，**复验回执为「已保存（修订 3）」**。
这类「后端确实写对了、回执却显示 undefined」的问题，只有真跑一遍界面才会暴露。

## 三、还没做

| 项 | 现状 |
| --- | --- |
| 新建笔记 | 界面没入口（`Upsert` 已支持 created） |
| 回收站查看与恢复 | 只能删，不能看回站内的笔记，也没有恢复入口 |
| 冲突的可视化 | 有中文提示与刷新，但没有并排对比旧稿/新稿 |
| 并发写入 | `SaveNote` 持读锁写库；单窗口场景没问题，多窗口同时编辑未做保护 |
| 知识库/标签/附件/向量写入 | 未做 |
| Windows/Linux、`.app` 签名 | 未做 |

**为什么先不补并发**：当前形态是单窗口预览；真正要支持多窗口，应该让写方法拿写锁并引入 SQLite 事务级重试，那是独立的一刀，不该混在「接界面」里。

## 四、下一步

2. 回收站列表与恢复（`Delete` 的逆操作要与 Rust `note_restore` 对拍）。
3. 再往后按 ADR-0007 迁 `media/backup` → `http/mail` → `chunker/embed` → `asr`。
