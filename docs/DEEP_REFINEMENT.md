# KnowFlick 深入优化记录

2026-10-02。承接 UI_REFINEMENT.md；覆盖 macOS 学习工作台、搜索、统计、保存反馈，以及 Android 统计、筛选、主题和语音控制器生命周期。按实际发现修复，没有给整个代码库打未经验证的“健康分”。

## 已落实

| 触发场景 | 原有问题 | 调整 |
| --- | --- | --- |
| 应用开着跨过午夜、修改时区、休眠后返回 | macOS 学习计划与侧栏缓存未刷新 | 监听日历、时区、时钟、唤醒和前台状态；只安排下一次午夜刷新，避免每分钟重绘整页 |
| 修改内容来源设置 | 未读卡堆变化，侧栏计数仍用旧缓存 | 观察派生卡堆计数 |
| 输入、筛选或统计状态更新 | 重复计算复习日期、排序和逐日遍历全库 | 计划一次聚合并缓存排程，未来日期按日汇总；统计快照按卡库与日期更新，7 天趋势取 35 天序列尾部 |
| 大量卡片集中在一天，或缩窄窗口 | 固定 600pt 掌握度条、未经归一化柱高可能溢出 | 使用可用宽度、扣除段间距；趋势按峰值归一化并补日期标签；热力图限宽 |
| 查看 macOS 复习统计 | 说明声称使用 SM-2，实际采用 1、3、7 天规则；复习数使用“人次” | 说明与实际算法一致，估算指标明确标为“掌握度估算”，单位改为“次” |
| 搜索条件连续变化、卡片被修改或关闭面板 | 防抖期间旧任务仍可提交；结果不随卡库变化更新 | 条件变化即令旧结果失效，关闭后禁止提交，观察卡库；限制选择索引，等待检索时阻止打开旧结果，不提前显示“未找到”；筛选补选中语义 |
| 设置写入失败但卡片写入成功 | 单一告警被卡片成功结果清除；退出同步保存忽略设置异常 | 分别保留卡片与设置告警，成功仅清理对应通道；即时保存与同步保存按各自 revision 提交结果 |
| Android 应用内时区发生变化 | 对象单例冻结旧时区，结果缓存缺时区键 | 每次统计获取当前时区，计划保留自身时区快照；统计页监听日期、时钟、时区及恢复前台 |
| Android 历史与收藏筛选 | 自制点击控件未提供选中语义，目标较小 | Tab 使用 selectable + Role.Tab，筛选使用 Material FilterChip，最小高度 48dp |
| Android 浅色按钮及 Material 弹层 | 琥珀色配白字对比不足，未配置角色继承默认紫色 | 深化浅色主色，显式设置前景与各容器角色，让控件沿用纸张配色 |
| Android 热力图连续活动超过 35 天或今天尚未活动 | 连续天数被显示窗口截断，并在当天活动前归零 | 连续活动使用完整日期集合并保留昨天宽限，35 天总数独立限期，补充单元格读屏文本 |
| Android 控制器离开其持有者 | 注释写弱引用，但静态字段实际强持有 SpeechController | 全局媒体控制入口改用 WeakReference；ViewModel 仍持有使用中的控制器 |

## 去模板化取舍

继续参考本机 ui-research 的信息分区、界面检查表与高频交互动效原则。保留内容摄影和原生控件，移除搜索面板微光渐变、统计交错入场、重复的掌握度总览；简化搜索提示、收藏/历史标签及主题说明。AI 来源标记仍保留，因为它表达内容来源。

- Android：269 项 JVM 测试，43 个套件通过；debug 安装包和 lint 检查通过。没有连接设备，未执行设备交互及后台媒体播控验收。
- 原生实屏：宣纸白首页、统计顶部、掌握度分布和到期预测通过；此前深色首页、复习、知识库与半屏布局已检查。解锁后完成中文全文搜索、拼音首字母、检索中状态、真实空结果与 Escape 关闭检查；暖曜黑主题已恢复，原外观模式偏好保留。
- Android lint 无错误，仍有 40 个既存警告和 2 项提示；本轮涉及文件的新提示已修正，静态控制器泄漏警告已消除。
- 未进行性能基准测量，因此不声明具体耗时降幅；本轮消除的是代码中可确认的重复扫描、排序与渲染驱动。

## 后续仍需专项处理

1. 双端排程模型不同：Android 支持已记录的动态 intervalDays，macOS 仍采用掌握度固定间隔。统一需要明确算法及旧数据迁移规则，不能只通过文案或 UI 替换。
2. Android 同步重试仍采用阻塞式等待，且吞掉 InterruptedException；取消同步应有独立集成测试后再改请求生命周期。
3. 语音后台播放、生命周期日期广播和读屏体验需在 Android 设备验收；当前构建与 JVM 测试不能替代。
4. 本轮未更改凭证迁移、同步协议和版本依赖；lint 中仍有既存的资源、Compose 规范与依赖提示，target SDK 35 是项目明确保留的行为版本决策。
