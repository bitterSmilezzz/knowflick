# 品味与可用性评审（2026-10-20）

> 目的：把「看起来对不对、用起来顺不顺」变成可复跑的判定，而不是一次性的肉眼结论。
> 门禁：`node tools/taste_usability_gate.mjs`（需运行中的 Vite + agent-browser）。

## 评审方式

不靠主观打分，先截图看全貌，再把能客观计算的部分写成断言：

1. 逐屏截图（库 / 收件箱 / 录入 / 复习 / 简报 / 问答 / 订阅 / 设置 / 深色 / 窄窗 / 胶囊）；
2. 用 DOM 计算对比度（WCAG AA）、点击目标尺寸、焦点环、侧栏裁切、横向溢出、重复 CTA；
3. 发现问题就改，改完重新跑门禁 —— 门禁本身就是这轮交付物。

## 这轮发现并修好的问题（都是截图或门禁实际暴露的）

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| 1 | 深色主题滚动条是浏览器默认亮白条，像渲染 bug | 深色截图里中栏右侧一条白边 | 用 token 画细滚动条，跟随主题 |
| 2 | 侧栏最后一行被硬切一半 | 截图里「温故复习」压在底边上 | 滚动区留 20px 下内边距 + 底部渐隐带 |
| 3 | 分类按字母序排，对使用频率没有信息量 | 截图里「心理学/架构/检索/物理」混排 | 按卡片数降序、同量按中文名；并显示计数 |
| 4 | 复习页「良好」按钮在评分前就高亮 | 截图里四个评分键唯独「良好」是选中态 | 改为推荐档边框，不再用选中态配色 |
| 5 | 复习页双滚动容器，底部按钮被遮 | 面板与卡片各滚一段 | 合成单一滚动容器 |
| 6 | 首次点开简报/问答/复习出现「正在加载…」 | 截图抓到了加载态 | 空闲时预取 lazy chunk |
| 7 | **空库时右栏完全空白** | 空库截图右侧一片白 | 给可执行引导（导入文件 / 添加订阅），并区分「无内容」与「筛选无结果」 |
| 8 | 补引导后出现重复 CTA（中栏「记录第一条」+ 右栏「记一条闪念」） | 门禁的重复 CTA 断言 | 右栏只补用户还没看到的入口 |
| 9 | **主按钮文字对比度 4.21:1，低于 AA 4.5** | 门禁量出的首个失败项 | 新增 `--accent-solid`：把 accent 朝黑压 22%，白字稳定 >6:1 |
| 10 | 修 #9 时把深色也朝白提亮，深色反而掉到 **3.55:1** | 门禁在深色场景失败 | 深浅两种模式都朝黑压；门禁复跑通过 |

第 9、10 两条值得单记：**改对比度时以为「深色要提亮」是常见错误**，实测 macOS 的 `AccentColorText` 在深色下同样是白字，提亮等于白字压浅底。这条只有真的量了才会发现。

## 门禁覆盖的九项

```
PASS 浅色主题下所有控件文字达到 WCAG AA
PASS 所有点击目标不小于 24px
PASS 深色主题下所有控件文字达到 WCAG AA
PASS 滚动条尺寸可测量（细条已生效）
PASS 空库右栏有可执行引导（导入文件 / 添加订阅）
PASS 同一屏没有重复 CTA
PASS Tab 顺序可达 12 个控件，全部有可见焦点环
PASS 侧栏滚到底时最后一行完整可见
PASS 没有横向溢出
```

## 明确没做的

- **没做真人用户测试**。上面的结论来自 DOM 计算与截图评审，不是可用性实验室数据；「新手能不能学会」这类问题需要真实用户。
- 点击目标下限取 24px（桌面紧凑工具条的合理值），没有套用移动端 44pt 标准 —— 这不是移动界面。
- 只覆盖浏览器渲染的同一套 React 界面；原生 Tauri 窗口的材质、交通灯、托盘菜单需要真机目视，脚本测不到。
