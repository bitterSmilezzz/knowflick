# 品味与可用性评审（2026-10-20）

> 目的：把「看起来对不对、用起来顺不顺」变成可复跑的判定，而不是一次性的肉眼结论。
> 门禁：`node tools/taste_usability_gate.mjs`（需运行中的 Vite + agent-browser）。

## 评审方式

不靠主观打分，先截图看全貌，再把能客观计算的部分写成断言：

1. 逐屏截图（库 / 收件箱 / 录入 / 复习 / 简报 / 问答 / 订阅 / 设置 / 深色 / 窄窗 / 胶囊）；
2. 用 DOM 计算对比度（WCAG AA）、点击目标尺寸、焦点环、侧栏裁切、横向溢出、重复 CTA；
3. 发现问题就改，改完重新跑门禁 —— 门禁本身就是这轮交付物。

## 这轮发现并修好的问题（都是截图或门禁实际暴露的）

| # | 问题 | 证据 | 修法 |
|---|---|---|---|
| 1 | 深色主题滚动条是浏览器默认亮白条，像渲染 bug | 深色截图里中栏右侧一条白边 | 用 token 画细滚动条，跟随主题 |
| 2 | 侧栏最后一行被硬切一半 | 截图里「温故复习」压在底边上 | 滚动区留 20px 下内边距 + 底部渐隐带 |
| 3 | 分类按字母序排，对使用频率没有信息量 | 截图里「心理学/架构/检索/物理」混排 | 按卡片数降序、同量按中文名；并显示计数 |
| 4 | 复习页「良好」按钮在评分前就高亮 | 截图里四个评分键唯独「良好」是选中态 | 改为推荐档边框，不再用选中态配色 |
| 5 | 复习页双滚动容器，底部按钮被遮 | 面板与卡片各滚一段 | 合成单一滚动容器 |
| 6 | 首次点开简报/问答/复习出现「正在加载…」 | 截图抓到了加载态 | 空闲时预取 lazy chunk |
| 7 | **空库时右栏完全空白** | 空库截图右侧一片白 | 给可执行引导（导入文件 / 添加订阅），并区分「无内容」与「筛选无结果」 |
| 8 | 补引导后出现重复 CTA（中栏「记录第一条」+ 右栏「记一条闪念」） | 门禁的重复 CTA 断言 | 右栏只补用户还没看到的入口 |
| 9 | **主按钮文字对比度 4.21:1，低于 AA 4.5** | 门禁量出的首个失败项 | 新增 `--accent-solid`：把 accent 朝黑压 22%，白字稳定 >6:1 |
| 10 | 修 #9 时把深色也朝白提亮，深色反而掉到 **3.55:1** | 门禁在深色场景失败 | 深浅两种模式都朝黑压；门禁复跑通过 |

第 9、10 两条值得单记：**改对比度时以为「深色要提亮」是常见错误**，实测 macOS 的 `AccentColorText` 在深色下同样是白字，提亮等于白字压浅底。这条只有真的量了才会发现。

## 门禁覆盖的九项

```
PASS 浅色主题下所有控件文字达到 WCAG AA
PASS 所有点击目标不小于 24px
PASS 深色主题下所有控件文字达到 WCAG AA
PASS 滚动条尺寸可测量（细条已生效）
PASS 空库右栏有可执行引导（导入文件 / 添加订阅）
PASS 同一屏没有重复 CTA
PASS Tab 顺序可达 12 个控件，全部有可见焦点环
PASS 侧栏滚到底时最后一行完整可见
PASS 没有横向溢出
```

## 易用性旅程走查（`tools/usability_journey_smoke.mjs`）

除了对单个控件做视觉和无障碍指标量化，我们在 `npm run gate:taste` 里合入了
12 个节点的核心用户旅程走查，真实模拟「一个从未用过的新用户从零开始」的操作全貌：

```
PASS 1. 首屏能看出下一步该做什么（空状态有可执行入口，无重复 CTA）
PASS 2. Cmd/Ctrl+N 打开录入对话框
PASS 3. 焦点自动落在正文输入框
PASS 4. 中文输入法组合期回车不误提交
PASS 5. 正文为空时提交给出可读错误（正文不能为空，记一句话也可以）
PASS 6. 成功保存后正文进入阅读区且输入框草稿清空
PASS 7. 页面刷新后新录入的内容完整保持
PASS 8. 搜索关键词命中并出现实体高亮（<mark>）
PASS 9. 搜不到时给出恢复路径（不留死路）
PASS 10. 真实键盘退格清空后列表立即恢复原状
PASS 11. 设置页保存给出明确文字回显（设置已成功保存）
PASS 12. 离开设置页后顺利返回主工作台
```

在走查中进一步发现并修复了一个真实体验问题：
- **空正文提交静默无反应**：对话框原先使用 `disabled={!canSave}`，当正文只有空格时按钮置灰点不动，且没有原因说明。现已改为按钮保持可点，点击后如果正文为空则在对话框内展示可读的错误提示「正文不能为空，记一句话也可以」，并且表单添加 `noValidate` 避免被 webview 原生样式粗糙的验证气泡接管。

## 明确没做的

- **没做真人用户测试**。上面的结论来自 DOM 计算与截图评审，不是可用性实验室数据；「新手能不能学会」这类问题需要真实用户。
- 点击目标下限取 24px（桌面紧凑工具条的合理值），没有套用移动端 44pt 标准 —— 这不是移动界面。
- 只覆盖浏览器渲染的同一套 React 界面；原生 Tauri 窗口的材质、交通灯、托盘菜单需要真机目视，脚本测不到。

## 复现

```sh
cd apps/workbench && npm run dev     # 终端 A
cd apps/workbench && npm run gate:taste   # 终端 B（等价于仓库根 node tools/taste_usability_gate.mjs）
```

这个门禁需要浏览器，所以**没有并进 `./tools/verify_workbench.sh`**（后者是 CI 的无浏览器门禁）。
两者分工：`verify_workbench.sh` 守「能不能用」，`gate:taste` 守「看起来对不对、用起来顺不顺」。

# 第二轮：深度界面走查（2026-10-20 深夜）

上一轮看完主界面就下了结论，这一轮把**没真正打开过的界面全部打开**，逐张看：AI 提炼预览、卡片详情、收藏、分类筛选、闪念胶囊（含多行）、素材 AI 入口、深色 + 窄屏、设置下半部分（插件 / 语义模型 / MCP）、空库。

## 这一轮发现并修好的问题

| # | 问题 | 严重度 | 证据 |
|---|---|---|---|
| 1 | **AI 提炼在浏览器模式被写死禁用** | 高（功能缺口） | `aiTransform` 第一行 `if (!inShell()) throw`，且 `completeChat` 直接 `invoke`。错误文案「浏览器体验支持本地整理」还是句废话——既没解决问题也没说清原因 |
| 2 | **面包屑残留上一屏选中项** | 中 | 从「收藏」点左侧分类，标题显示「收藏」，面包屑却显示「收藏 / 计算机」 |
| 3 | **胶囊标题 ⌥ 字形渲染成方框** | 低（可见瑕疵） | 部分 webview 字体缺该字形 |

### 1. AI 提炼打通浏览器路径

`completeChat` 增加浏览器回退：非 shell 时走 `fetch` 直连，并按域名区分 Anthropic 的 `x-api-key` / `anthropic-version` 与 OpenAI 的 `Authorization: Bearer`。跨域被拒时错误明确说「跨域被拒绝 + 建议去桌面端」，不再让用户猜。

同时删掉 `aiTransform` 的 `inShell()` 硬闸。

**真实验证**：用 mock 的 SSE/JSON 响应把预览对话框真实渲染出来——三张卡、复选框、`已勾选 3 / 3` 计数、取消全选、确认保存全部可用。这是此前从未在真界面上看过的核心流程。

### 2 & 3

分类点击统一走 `navigate()`（它清 `selectedId`），面包屑不再污染；胶囊快捷键标签改用 ASCII `Option+Space`。

## 补的测试

`src/domain/ingest.aiPreview.test.ts` 6 项，锁住 AI 输出解析行为：标准数组、前后带解释文字、`details < 80` 丢弃、同题去重、无数组报错、缺 `category` / `summary` 时兜底。最后一条正是这次踩到的——mock 的正文太短被静默过滤，错误提示却是「没有可用的新卡片」，容易误判成产品 bug。

## 顺带查明的一个「假问题」

一度以为「本地语义检索面板塌陷、标题被挤出可见区」，量过 DOM 后发现面板结构完好（宽 560、头高 68），塌陷只是我截图时只滚到面板一半。**先量再下结论**，否则会把测试脚本的问题当成产品缺陷去「修」。
