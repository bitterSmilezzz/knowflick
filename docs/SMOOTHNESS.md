# 丝滑清单：把「卡一下」的地方逐个拆掉

> 目标不是「功能存在」，而是**每一步都不卡、不猜、不等**。
> 这份文档记录已经量过／修过的地方，以及实测后判定**不需要动**的地方。

## 一、已修：批量导入不再一错全废

**症状**：选十个文件、其中一个格式不支持，前面的导入了、后面的全不处理，
用户只看到一句「导入未全部完成」。

**原因**：`importFiles` 里任何一处 `throw` 都会跳出整个 `for` 循环。

**现在**：逐文件处理，结果分三桶——成功 / 与库里内容相同已跳过 / 失败，
汇总按桶报数，失败项逐条写原因；全部失败时说「没有文件导入成功」。

## 二、已修：图片终于能作为来源

**症状**：用户把图片列为来源之一，导入却直接报「暂不支持这种格式」。

**现在**：`.png / .jpg / .jpeg / .webp / .gif / .heic` 作为独立素材类型入库；
附件走 `media/image/`（16 MiB 上限、图片 MIME 白名单、原子写、拒绝路径穿越）；
阅读区直接显示图片。CSP 相应放开 `img-src` / `media-src` 的 `blob:`，
其余仍锁在 `'self'`。

## 二·补：PPT 终于能导入

**症状**：用户把 `ppt` 列在来源里，导入只认 Word/PDF，遇到 PPT 直接报「暂不支持这种格式」。

**现在**：`parsePptxBuffer` 复用已有的纯 JS ZIP 解压器（不引入依赖），
取 `ppt/slides/slideN.xml`，按**编号**排序（按字符串排会让 `slide10` 跑到 `slide2` 前面），
提取 `<a:t>` 文本并按页拼成 Markdown。只取文字，不还原版式/图形/备注——
目标是能搜到、能被 AI 提炼。XML 实体会还原，纯图片 PPT 与「根本不是 PPTX」
分别给出可读原因。旧版 `.doc/.ppt/.xls` 明确提示「请另存为 .docx 等」。

**当前支持的来源**：

| 类型 | 状态 |
| --- | --- |
| Markdown / TXT / JSON | ✅ |
| Word (.docx) | ✅ |
| PowerPoint (.pptx) | ✅ |
| PDF | ✅ |
| 图片 (.png/.jpg/.webp/.gif/.heic) | ✅ 作为素材，不做 OCR |
| 旧版 .doc/.ppt/.xls | ❌ 提示另存为新格式 |
| Excel (.xlsx) | ❌ 尚未支持 |
| 邮箱 / 订阅源 / 剪藏 / 手写 / 语音 | ✅ 各自独立入口 |

## 三、已修：长操作有具体反馈，且有出口

**症状**：AI 归纳、转写、抓取订阅、恢复备份期间，界面只是按钮变灰，
状态栏永远显示「已保存到本机」——看不出在等什么，也没有退出的办法。

**现在**：

- 状态栏显示具体动作：`正在转写语音…`、`正在抓取「X」…`、`正在导入 3/8`、`正在恢复备份…`。
- 浏览器模式的 `fetch` 补上 **120 秒超时**（桌面端 reqwest 本来就有 120 秒）。
  超时提示写明「模型 120 秒没有响应，已中止……已保存的内容不受影响」。

## 四、已修：内容去重

**症状**：`contentHash` 字段从建库起就存在，但**从未被赋值、也从未被检查**，
所以同一个文件导入两次就是两份重复素材。

**现在**：`contentHashOf` 用 FNV-1a 32 位 + 长度前缀（不是密码学哈希，只用于去重），
忽略行尾与首尾空白，空内容不生成指纹。图片按「文件名 + 字节数」判重。

## 五、已修：搜索覆盖（「明明有却搜不到」）

搜索是最常用的动作，覆盖不全就是最难受的卡点。**先写测试证明缺口，四条当场全失败**：

| 缺口 | 现象 |
| --- | --- |
| 卡片只搜 `details`，**不搜 `summary`** | 用户记住的往往正是那句结论，却搜不到 |
| 卡片只搜 `links[0]` | 从第二条链接起搜不到 |
| 邮件标为 `tags: []`，正文里没有发件人 | **按发件人搜不到** |
| 附件名不在任何搜索字段里 | 搜附件名搜不到 |

修法：

- 素材搜索文本摊平 `cleanedMarkdown` 与 `metadataJson` 里的
  `from / to / subject / fileName / mime / attachmentFilenames`。
  **坏元数据退回只搜正文**，不让整条素材从结果里消失。
- 卡片搜索文本包含 `summary + details + 全部链接标题与地址`。
- 顺带补上 `image / audio / ink` 三种来源的中文分类名（之前全显示「闪念」）。
- 占位文案改为「搜索标题、正文、发件人、附件或标签」，与实际覆盖一致。

**性能核对**：`entriesFor` 现在会解析 `metadataJson`，但它是按
`[materials, cards, collection]` 记忆的，不会随每次击键重算。
实测 200/1000/3000 条打开到可交互仍是 ~357 ms，与改动前一致，无回归。

## 六、已修：温故复习的两处自相矛盾

查复习页时发现两件事叠在一起：

1. **`dueOnly` 默认 false**，复习页把所有卡都排进队列——「今日待复习 0」下面紧接着
   出现一张待评分的卡，计数与界面自相矛盾，FSRS 排期也形同虚设。空态有文案，
   但**没有任何出口**。
2. 只把 `dueOnly` 打开会引入更严重的问题：`reviewDay` 对「从未看过」的卡返回 `null`，
   新卡因此**永远不算到期**——新建的卡再也进不了复习队列，库越攒越多却一次都没复习过。

修法：

- 新增 `reviewQueue` = **到期卡在前、从未过目的新卡在后**（两类含义不同：到期是
  「该看了」，新卡是「还没看过」），并受上限约束（默认 20）。
- 复习页改用 `reviewQueue`；空态文案说明「记忆算法已把 N 张卡排到之后」，
  并给显式出口「仍要复习全部（额外练习）」——只有额外练习才用全库队列。

## 七、已修：备份不带附件（最重的一项）

**症状**：设置页写着「数据完全归你所有」，但 `.kfbackup` 只打包 `materials.json`
里的 `mediaPath` 字符串，**从不带媒体字节**。换一台机器恢复后那些路径指向空处，
阅读区读取失败又静默不显示——用户以为备份完整，实际录音与图片已经丢了。

**修法**：

- 打包：附件按库内相对路径作为 ZIP 条目一起带走，`manifest.stats.media` 记数量。
- 解包：新增 `unpackZipStoreBinary` 保留原始字节（文本解码会把音视频搅坏）。
- 还原：只接受 `media/(audio|image|ink)/` 白名单路径，备份包里夹带的越界路径一律不还原；
  按扩展名还原白名单 MIME 再落盘（用 `application/octet-stream` 会被类型白名单全部判失败）。
- 导出：逐条读字节，**单条缺失只跳过该条**，不阻断整份备份；完成提示带上附件数量。

同轮顺带修的潜伏缺陷：

- `saveMedia` / `readMedia` 写死 `dir: null`，自定义库目录时附件会写到默认库；
  现在与其它 shell 调用一样透传 `dir`。
- 附件读取失败不再静默留白，提示「附件没能读取（可能已被移动或删除）」。

## 八、工具：打包安装一条链

连续三次 `tauri build --bundles dmg` 都因上一次失败留下的 `/Volumes/dmg.*`
残留挂载而失败。现在用 `./tools/install_workbench_macos.sh [--no-build]`
一条命令做完：清理残留挂载 → 退掉运行中的实例 → 打包 → 拷到临时名再替换 →
trap 兜底卸载 → 确认进程真的起来。

写脚本时踩到仓库已有 linter 覆盖的坑：`$TARGET（` 里的全角括号会被 bash 并进
变量名，报 `TARGET<0xEF>: unbound variable`，只在 UTF-8 locale 下复现。
已改用 `${TARGET}`，并把 `tools/lint_shell_vars.sh` 加进 `verify_workbench.sh`
（原来只有 android.yml 跑），本地就能挡住。

## 七·补：应用阶段——批量操作与「点了没反应」

### 批量操作

产品要求里写过「对知识做应用做总结做一系列操作」，但列表一直是**单选**：
点谁选谁，整理几十张卡只能一张张点。

- ⌘/Ctrl（Shift 也接受）点击追加或取消；普通点击仍是单选并**退出多选**。
- 换页 / 换筛选自动清空选择，不留看不见的待处理选择。
- 多选知识卡时出现批量栏：**标记已复习 / 收藏 / 设统一分类** + 退出。
- **批量栏只对卡片开放**：素材是原始记录，归档走收件箱语义。
- **键盘也能多选**：Shift+方向键做范围选择；已在最后一行时不会越界扩展。
- 设分类用内联输入，替换掉原生 `window.prompt`。

### 问答的对话一离开就清零

`messages` 只是 `useState`，没有任何持久化：问几句、切到别的页面再回来，
整段对话就没了。问答是应用阶段的核心，问完就忘等于每次从零开始。

- 对话存到本机（`knowflick.workspace.chat`），**切页、刷新、重启后都还能接着问**。
- 读取时逐条校验：坏数据、空内容、非法 role 一律丢弃；整段坏掉就退回问候语，
  不让一条脏数据把问答页打不开。
- 只留最近 **40 轮**；写入失败（存储满）只放弃持久化，对话仍在内存里。
- 有对话时提供「清空对话」，并说明「对话会保存在本机」——有持久化就必须有清空的出口。

### 简报「重新分析」看起来像没反应

它是纯本地重算（不依赖模型），但卡片没变时结果完全一样。现在按下后按钮文案
短暂变为「已按当前卡片重算」。

### 未配密钥时提问「点了没反应」

守卫写成 `needsKey && inShell()`——只在桌面端拦截。浏览器模式下即使明知没有
密钥，也会发出一个注定失败的请求，界面要转到 **120 秒超时**才报错。

现在两种模式都先拦一次并说明「若服务端不需要密钥，再点一次即可继续」，
确认后不再重复拦截。既不让人干等，也不封死自建的无密钥服务端。

同时补上「应用」阶段的第一条自动化覆盖：`brain_ui_smoke`（16 项），
覆盖问答的密钥守卫与二次确认、**对话的切页/刷新持久化与清空**、
简报的结构化板块、可执行动作与重新分析的反馈。

## 七·补·旧：应用阶段的批量操作

产品要求里写过「对知识做应用做总结做一系列操作」，但列表一直是**单选**：
点谁选谁，整理几十张卡只能一张张点。这是应用阶段最大的缺口。

- ⌘/Ctrl（Shift 也接受）点击追加或取消；普通点击仍是单选并**退出多选**，
  不留下看不见的待处理选择。
- 换页 / 换筛选自动清空选择：旧选择多半已经不可见，留着容易误操作。
- 多选知识卡时列表顶部出现批量栏：**标记已复习 / 收藏 / 设统一分类** + 退出。
  三个操作都写回全部选中卡片，并回执「已处理 N 张卡片」。
- **批量栏只对卡片开放**：素材是原始记录，归档走收件箱语义，
  不在这里批量处理——避免给一个「批量删素材」的假入口。
- 被勾选的行有可见标记（左侧强调色竖条 + 淡底），不只靠颜色区分。

回归里踩到两件事：

1. **两次 ⌘ 点击连着 dispatch 会打到同一批旧节点**——选中态变化会让列表重渲染。
   改成两次独立点击（间隔 350ms），这也更接近真实操作序列。
2. **带条件的断言等于没有断言**：卡片数不足 2 时整段批量断言永远不执行、
   也不报错，通过时一声不吭。改成先补足第二张卡再断言，保证断言真的会跑。

## 八·补：备份带走附件后的三个连带修复

- **只有素材的旧备份不再被标成失败**：`knowflick-workspace` 分支先落库素材，
  又要求 `cards` 必须是数组，于是同一份文件既报「已导入 N 条」又报「以下文件没有导入」。
- **附件报错中文化**：`media.rs` 暴露给用户的 10 条错误原是英文（路径无效、附件过大、
  写入不完整…），一律改成中文。
- **图片上限前后端对齐**：前端允许 32 MB、后端只收 16 MB，20 MB 的图会一路走到写入阶段
  才收到英文报错；现在导入时先按 16 MB 拦截并用中文说明。
- **库目录透传 + 附件缺失提示**：`saveMedia`/`readMedia` 原先写死 `dir: null`，
  自定义库目录时会写到默认库；现在与其它 shell 调用一致。读取失败不再静默留白。

## 九、一条验证纪律（CI 教会的）

有一轮我用 `grep -E "Test Files|..." ./tools/verify_workbench.sh` 来读结果，
**没看退出码**：`set -e` 下 `tsc` 失败会中止脚本，但 grep 仍会打印前面匹配到的行，
看起来像全绿。结果提交后 CI 的 `tsc` 步骤报 `TS18048`，本地却一路"通过"。

**门禁一律这样跑**：

```sh
./tools/verify_workbench.sh > /tmp/verify.log 2>&1; code=$?; echo "exit=$code"; ...
```

grep 只用来读摘要，判断"是否通过"必须看 `exit=`。

## 十、实测后判定**不用动**的地方

避免拍脑袋优化，这两处是量过才下的结论：

| 项目 | 实测 | 结论 |
| --- | --- | --- |
| 长列表性能 | 200 / 1000 / 3000 条，打开到可交互分别 ~408 / ~366 / ~443 ms | 不做虚拟化 |
| 列表分页 | 首屏固定 60 行，「加载更多（还有 N 条）」可用，点一次 60 → 120 | 已够用 |

列表本来就有 `visibleCount` 分页，不是静默截断——这条也进了门禁断言
（只有真被截断时才要求出现「加载更多」）。

## 十一、边界

1. **去重是精确匹配**，不是模糊相似度：改一个字就是新内容。想合并相近内容得靠后续的整理功能。
2. **图片不参与全文检索**：没有 OCR，图片素材按标题与文件名可搜。
3. **120 秒超时对长报告可能偏短**：超时后已保存内容不受影响，但需要重试。
4. **首屏 60 行是写死的**，没有按窗口高度自适应。
5. 真机（Tauri）里只确认了界面与命令存在，**录音与图片附件的真机链路尚未逐步点过**。
