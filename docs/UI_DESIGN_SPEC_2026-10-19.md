## 0. 一次说清当前为什么不好看

调研（2026-10-19，带代码取证）确认不美观主要不是审美问题，而是三处叠加：

1. **两套设计系统同时生效**：旧 `styles.css` 在构建产物里排在 `workspace.css` 之后，于是旧规则赢了——所有按钮实际是 `32px / border-radius:8px`（`styles.css:79-88` 覆盖 `workspace.css:4`），控件字体经 `font: inherit` + `body` 衬线变成衬线字（`styles.css:74,77`），简报页标题按 28px 衬线渲染（`.detail h1` 优先于 `.ws h1`）；未加作用域的 `[data-paper=…]` 让暖赭 `--accent` 覆盖灰绿 `--ws-accent`（`styles.css:1-64` vs `workspace.css:1-3`）。
2. **字号过小**：工作区用 8/9/10/11/12/13px 体系，最小 8px；侧栏正文与分组标签只有 10–12px。
3. **右栏默认是营销式欢迎页**：`Workspace.tsx:149` 的 -5° 倾斜图标、英文 eyebrow、01/02/03 三步。

附带事实：中栏条目固定 `min-height:134px`（`workspace.css:6`），最小窗口 880px 下右栏只剩约 415px 却要排 26px 标题与 14px/行高 2.0 正文（`tauri.conf.json:18`）；侧栏文字对比度 4.07:1 未达 WCAG AA 4.5:1；结构细线 1.20–1.35:1。

## 1. 设计原则（已确认）

| # | 原则 | 含义 |
|---|---|---|
| P1 | **平台原生优先** | macOS / Windows / Android / 未来 iOS 各自遵循本平台的窗口、导航、控件与交互习惯，共享信息结构与少量品牌元素。**不是每端重写一套**：同一份 Web 代码 + 平台接缝。 |
| P2 | **安静细腻的原生工具感** | 内容为主，颜色少，层次细微；不做装饰性渐变、不做统一大圆角卡片墙。 |
| P3 | **舒适易读，按需展开** | 正文与列表优先可读；常用操作直接可达；低频元数据、AI 动作、高级选项在选中内容或主动展开后出现。 |

## 2. 排版基线（已确认）

- 正文 **14px / 行高 1.6**；**最小 12px**，不再出现 8–11px。
- 标题：页面标题 17px 600；面板标题 14px 600；列表标题 14px 500。
- 摘要与正文同尺寸时用中性色降级，不靠缩小字号。
- 元信息 12px，颜色必须满足对比度（见 §4）。
- 字体栈按平台取系统字体；正文中文优先 `"PingFang SC"` / `"Microsoft Yahei"` / `system-ui`，**控件一律无衬线**；不引入外部字体文件。
- 行宽：正文测量宽度控制在约 68 个中文字符以内（约 60–76 拉丁字符），不铺满超宽窗口。
- **色调方向：中性偏冷灰**（浅色背景 `#F5F6F7` / 内容面 `#FFFFFF` / 正文 `#1C1E20`；深色 `#1B1D1F` / `#232629`）。深色不是浅色反相，需单独调校层次。
- **默认外观：跟随系统**（三档中的默认值）。

## 3. 控件几何（已确认）

- 高度：按钮与输入框 **28–32px**。
- 圆角**只用两档**：控件 **4px**，面板与浮层 **8px**。删除现有 6/7/9/10/12/20px。
- 描边 1px hairline；不用投影表达层级，必要时用极轻的边框与底色差。
- 图标：统一线性图标体系，笔画 1.65px（`viewBox 24` 下），尺寸 14/16/18/22 四档，不用 emoji、不混用填充图标（状态星标除外）。
- 焦点环：`outline-offset: 0` 或内缩，避免被 `overflow: hidden` 裁切；对比度 ≥3:1。

## 4. 颜色与主题（已确认）

- 主题**三档**：`跟随系统 / 浅色 / 深色`，**默认跟随系统**。删除宣纸白、羊皮纸、晨雾灰、暖曜黑等旧名称与对应空承诺样式。
- **中性色为主体**，强调色默认跟随系统；用户可覆盖。选中、焦点、主要动作使用强调色，其余低彩度。
- 不再有品牌固定绿色；不保留 `--accent: #80591d` 暖赭。
- 侧栏与列表**不使用彩色圆点**区分条目（原生侧栏惯例）。
- 硬性对比度要求（WCAG 2.2 AA），下表为**已实测**取值（按 WCAG 相对亮度公式复算）：

| 用途 | 取值 | 对比度 | 判定 |
|---|---|---|---|
| 浅色正文 | `#1C1E20` on `#FFFFFF` | 16.72:1 | ✅ |
| 浅色次要文字 | `#5F666E` on `#FFFFFF` / `#F5F6F7` | 5.81:1 / 5.37:1 | ✅ |
| ~~`#6B7280` on `#F5F6F7`~~ | 4.47:1 | ❌ **不可用于正文级文字**（此值即上一版侧栏 4.07:1 类问题的近亲） |
| 深色正文 | `#E6E8EA` on `#232629` | 12.38:1 | ✅ |
| 深色次要文字 | `#A3AAB3` on `#232629` / `#1B1D1F` | 6.49:1 / 7.21:1 | ✅ |
| 强调色 | `#2F6FD0` on `#FFFFFF` | 4.88:1 | ✅ |
| 结构细线 | `#E3E6E9` on `#FFFFFF` / `#33383D` on `#232629` | 1.25:1 / 1.28:1 | ⚠️ 仅可作**纯装饰分隔**；承载信息的控件边框必须另取更深值（≥3:1） |

  - 正文与次要文字 ≥ **4.5:1**；
  - 承载信息的控件边框与图标 ≥ **3:1**（纯装饰分隔线可豁免，但需逐处判定并在此登记）。

## 4.1 视觉稿结论（2026-10-19 三稿对比后定稿）

三份真实排版稿（同内容、同画布 1040×760）已渲染核对，产物在 `.scratch/ui-directions-2026-10-19/`（不入库）：

| 稿 | 栏宽 导航/列表/正文 | 列表行高 | 正文留白 | 结果 |
|---|---|---|---|---|
| **A 克制型** | 200 / 320 / 520 | **56px** | 32px | ✅ **选定为基线**：同屏约十条收藏 + 456px 舒适正文宽度，扫描与阅读最均衡 |
| B 精炼型 | 200 / 340 / 500 | 48px | 28px | 备选密度（摘要仅一行、正文略窄） |
| C 呼吸型 | 224 / 304 / 512 | 72px | 40px | 备选长文模式（同屏条目少约三成；880px 窗口下阅读区仅约 352px） |

已随选定一并确认：
- **列表条目 = 双行**：第一行「标题 + 时间」，第二行「来源 + 摘要」；长标题与摘要在列表内截断，完整内容在右栏。
- **强调色跟随系统**：读取平台系统强调色（macOS 可在系统设置更改），截图中的冷蓝 `#315E8B` 仅为示意值；用户可在设置中覆盖。
- 三稿共同基线已核验：正文 14px / 行高 22.4px、可见最小文字 12px、控件 30–32px、圆角仅 4/8px、无外部依赖、无整页滚动、每栏独立滚动、Overlay 顶栏与交通灯同行且左上 78px 避让。

## 5. 布局（已确认）

- **可调整、可收起的三栏**：导航 / 列表 / 正文。
  - 分隔条可拖动，宽度记忆；
  - 每栏可收起，收起后以窄条或按钮恢复；
  - 窄窗口不硬塞三栏：按可用宽度减少栏数（窗口宽度优先，不按设备）。
- 面板尺寸：导航 200–260px，列表 280–360px，正文自适应并受行宽上限约束。
- **窄窗口行为（已确认）**：窗口宽于约 1100px 时三栏；更窄时**自动收起导航**，只留列表 + 阅读；需要导航时用顶栏按钮或快捷键滑出。880px 最小宽度下仍按此规则，不硬压三栏。
- **录入界面（已确认）**：窗口内居中面板（非全局悬浮窗、非底部滑条），保持现有 dialog 行为、按本规范重做视觉。
- **系统菜单（已确认）**：补齐原生菜单栏——macOS 提供应用/文件/编辑/显示菜单，含「记录一件闪念 ⌘N」「搜索 ⌘K」「切换侧栏 ⌃⌘S」等；Windows 提供对应菜单。
- 材质克制：**框架区**（侧栏、标题栏、浮层）可使用平台材质；**正文与列表保持清晰实底**。
- 不使用整页滚动；每栏独立滚动。工具栏高度 38–44px。

## 6. 关键界面规则（已确认）

- **落地页**：恢复上次工作位置；首次打开空库进入收件箱。
- **列表**：精致平面列表；标题 + 摘要 + 少量来源信息；图片/视频显示小缩略图，纯文字不配图；选中状态轻而明确。去掉固定 134px 行高。
- **阅读与编辑**：默认优雅阅读，主动进入编辑；阅读时正确排版标题、列表、引用、链接、代码。
- **AI**：随当前内容按需出现；阅读时不常驻聊天框；保留可发现的问答入口。
- **空状态**：极简——一行状态说明 + 一个主操作（记录）+ 一个次操作（导入），无英文标语、无 01/02/03 步骤。

## 7. 动效（已确认）

- 只做回答用户动作的动效，不做装饰性入场；单次编排优先于到处淡入。
- 时长 90–150ms，缓动收尾；不使用 400ms+ 飘浮感过渡。
- 必须纳入 `prefers-reduced-motion` 守卫（当前划卡过渡未覆盖，需补）。

## 8. 平台接缝（已确认全做，属同一份代码）

| 效果 | 接缝 |
|---|---|
| macOS 标题栏与交通灯融合 | Tauri `titleBarStyle: Overlay` + 自建 drag region，顶栏避让交通灯宽度 |
| Windows Mica 材质 | Tauri `windowEffects`（平台各自映射；不支持时回退纯色） |
| 系统深浅实时跟随 | `matchMedia` 监听写入主题状态（当前无监听，需重载才切换） |
| 系统钥匙串存 API Key | 平台接缝（当前为数据目录文件，如实披露） |

Windows 系统字体与 4px/8px 圆角**只需 CSS 令牌，无需重写**。

## 9. 工程清理（属实现范围，不需用户决策）

1. 删除 `apps/workbench/src/App.tsx` 与其独占组件（`CardSheet`、`HelpSheet`、`ImportRestoreSheet`、`SearchSheet`、`InboxView`、`QuickCaptureModal`）——现已被 `Workspace` 取代且无人引用。
2. 删除或收编旧 `styles.css`：迁移仍被使用的页级样式（简报/问答/复习）到统一令牌，消除构建顺序导致的覆盖。
3. `paperTheme` 加白名单校验（当前不校验，旧值会写进 `data-paper`）。
4. 快捷键符号按平台取 `⌘ / Ctrl`（当前硬编码 `⌘`，Windows 会显示错）。
5. 划卡过渡补 `prefers-reduced-motion` 守卫。

## 10. 验收方式

- 每个界面改动都在真实尺寸窗口（含 880px 最小宽度与 1440px 宽屏）截图核对，不接受只看编译。
- 对比度按 WCAG 公式逐处复算，不靠肉眼。
- 保留现有 `tools/workspace_ui_smoke.mjs` 行为回归，新增折叠栏与主题切换断言。
- 深浅两套皮肤都要检查；浅色与深色不是简单反色。
